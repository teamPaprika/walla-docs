# Internationalization (i18n) Guide

This project supports full internationalization with English and Korean languages.

## Features Implemented

### 1. Automatic Language Detection ✅

The application automatically detects the user's preferred language based on their browser's `Accept-Language` header.

**How it works:**
- When a user visits the site for the first time, the middleware reads their browser's language preference
- If the browser language is Korean (ko), they are redirected to `/ko/docs`
- If the browser language is English (en) or any other language, they see the English version at `/docs`
- The detection happens automatically via the i18n middleware in `src/middleware.ts`

**Example:**
- User with Korean browser (Accept-Language: ko-KR) → Automatically redirected to `/ko/docs`
- User with English browser (Accept-Language: en-US) → Stays at `/docs`
- User with Japanese browser (Accept-Language: ja-JP) → Falls back to `/docs` (English)

### 2. Manual Language Switcher ✅

Users can manually change the language at any time using the language selector in the navigation bar.

**How to use:**
1. Look for the language selector in the top navigation bar
2. Click on it to see available languages:
   - **English** - English version
   - **한국어** - Korean version
3. Select your preferred language
4. The page will reload with the selected language

**Location:** The language switcher appears in the navigation bar on all documentation pages.

### 3. Language-Specific URLs

Each language has its own URL structure:

- **English (Default):** `/docs/*`
  - Example: `/docs/authentication`
  - No language prefix (cleaner URLs for default language)

- **Korean:** `/ko/docs/*`
  - Example: `/ko/docs/authentication`
  - Clear language prefix in the URL

**Benefits:**
- URLs are shareable with language preference preserved
- Search engines can index both language versions separately
- Users can bookmark pages in their preferred language

### Configuration

**i18n Configuration (`src/lib/i18n.ts`):**
```typescript
export const i18n = defineI18n({
  defaultLanguage: 'en',
  languages: [
    { name: 'English', locale: 'en' },
    { name: '한국어', locale: 'ko' },
  ],
  hideLocale: 'default-locale', // Hides /en prefix
});
```

**Middleware (`src/middleware.ts`):**
- Automatically detects browser language preference
- Redirects to appropriate language version
- Handles locale routing

**Layout (`src/app/docs/layout.tsx`):**
- Provides language-specific page tree
- Applies UI translations based on locale
- Renders language switcher

## For Developers

### Adding a New Language

1. Update `src/lib/i18n.ts`:
```typescript
languages: [
  { name: 'English', locale: 'en' },
  { name: '한국어', locale: 'ko' },
  { name: '日本語', locale: 'ja' }, // New language
]
```

2. Create translations in `src/lib/i18n-strings.ts`:
```typescript
export const jaTranslations: TranslationFile = {
  search: '検索',
  // ... other translations
};
```

3. Update layout to apply translations:
```typescript
translations:
  lang === 'ko' ? koTranslations :
  lang === 'ja' ? jaTranslations :
  undefined
```

4. Create content directory:
```bash
mkdir -p content/docs/ja
# Add translated .mdx files
```

### Translation Guidelines

When translating documentation:

1. **Preserve Technical Terms:**
   - Keep API endpoints unchanged: `/open-api/v1/workspaces`
   - Keep code examples in original form
   - Keep JSON keys unchanged: `customerKey`, `formId`

2. **Translate User-Facing Content:**
   - Headings and descriptions
   - Table headers and content
   - Inline notes and callouts
   - Navigation text

3. **Update Internal Links:**
   - Add language prefix to links: `/docs/auth` → `/ko/docs/auth`
   - Use Cards component with localized hrefs

4. **Maintain Structure:**
   - Keep same MDX frontmatter structure
   - Preserve code fences and syntax highlighting
   - Maintain same heading hierarchy

## Testing

### Test Automatic Detection

1. **Chrome/Edge:**
   - Settings → Languages → Add Korean
   - Move Korean to top of preferred languages
   - Open incognito window and visit the site
   - Should automatically redirect to `/ko/docs`

2. **Firefox:**
   - Settings → Language → Choose → Add Korean
   - Move Korean to top
   - Open private window and visit the site
   - Should automatically redirect to `/ko/docs`

### Test Manual Switching

1. Visit `/docs` (English)
2. Click language selector in navigation
3. Select "한국어"
4. Should navigate to `/ko/docs`
5. Click language selector again
6. Select "English"
7. Should navigate back to `/docs`

4. Visit `/docs/authentication`

## User Experience

### First-Time Visitors

1. **Automatic Guidance:**
   - Browser language is detected
   - User is redirected to their preferred language
   - No manual action required

2. **Manual Override:**
   - If automatic detection chooses wrong language
   - User can manually switch using the language selector
   - Preference is maintained through navigation

### Returning Visitors

- URL-based language preference
- If they bookmark a Korean page, they'll return to Korean
- If they bookmark an English page, they'll return to English

### Language Switcher Behavior

- Always visible in navigation
- Shows current language
- Dropdown shows all available languages
- Clicking a language immediately switches
- Page content updates without losing place in navigation

## SEO Considerations

- Each language version has unique URLs
- Search engines can index both versions separately
- `lang` attribute is set correctly in HTML (`<html lang="ko">`)
- Content is properly localized for target audience
- No duplicate content issues (different URLs)

Language detection respects the browser's `Accept-Language` header, which is supported by all major browsers.

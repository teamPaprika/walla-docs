# Internationalization guide

## Supported languages

The source of truth is `src/lib/i18n.ts`. All languages use an explicit URL prefix.

| Language | Locale | Display name | Help center |
| --- | --- | --- | --- |
| English (default) | `en` | English | `/en/docs/help-center` |
| Korean (source) | `ko` | 한국어 | `/ko/docs/help-center` |
| Traditional Chinese | `zh-TW` | 繁體中文 | `/zh-TW/docs/help-center` |
| Japanese | `ja` | 日本語 | `/ja/docs/help-center` |
| Spanish | `es` | Español | `/es/docs/help-center` |
| Brazilian Portuguese | `pt-BR` | Português (Brasil) | `/pt-BR/docs/help-center` |

## Language selection

The static site's root page (`src/app/page.tsx`) redirects in the browser. A supported
`lang` cookie takes priority, followed by `navigator.language`, then English.
Portuguese browser locales, including `pt`, `pt-BR`, and `pt-PT`, use the Brazilian
Portuguese translation. Traditional Chinese matching preserves the existing regional
rules. A language selection is saved for one year by `LangCookie`, which also updates
the document language for assistive technology after hydration. The locale layout
also marks server-rendered content with its language before hydration.

The language menu and documentation controls are translated in
`src/lib/layout.shared.tsx`. Section tabs are in `src/app/[lang]/docs/layout.tsx`.

## Content and translation scope

Korean (`content/docs/ko`) is the source of truth. Preserve the same relative file
paths, MDX component structure, code examples, assets, and navigation page slugs.
Translate headings, descriptions, body text, image alt text, UI labels, and navigation
titles/separators. Internal article links should use the destination locale.

Brazilian Portuguese covers every public help-center article and the four developer
introduction guides (`index`, `quick-start`, `authentication`, `error-codes`). As with
Spanish, Japanese, and Traditional Chinese, detailed API/Custom Field SDK references
and the internal style gallery use the existing English fallback. These intentional
exceptions are listed in `content/docs/.i18n-ignore`.

| --- | --- |
| Form / 설문 | formulário |
| Field / 항목 | campo |
| Response / 응답 | resposta |
| Workspace | espaço de trabalho |
| Team | equipe |
| Logic | lógica |
| Branching | ramificação |
| Reward | recompensa |

Use Brazilian Portuguese conventions and natural direct instructions. Preserve
product names, API identifiers, plan restrictions, currencies, and country-specific
availability. Existing screenshot references remain unchanged; translate their alt text. The existing
MDX pipeline hides screenshots and videos in all non-Korean locales, including pt-BR.

## Search

Search indexes are exported separately at `/api/search/{locale}`. The server's
`localeMap` explicitly maps `pt-BR` to Orama's `portuguese` tokenizer; the search client
uses the same language when loading that index. Both sides must match for accented
words and Portuguese tokenization to work consistently.

## Verification

Before review, run:

```sh
pnpm i18n:check
pnpm types:check
pnpm build
```

The drift checker reports missing pages, Korean sources newer than their translations,
and mismatched navigation page lists. It reads per-file Git timestamps, using mtime
for uncommitted files. Commit translations together with or after the source change.
Only run `pnpm i18n:accept` after manually verifying that flagged translations already
match their Korean sources; it records source hashes to silence timestamp-only drift.

Check the language menu, Portuguese browser redirect, an article with images and
steps, mobile navigation, and searches with and without accents in a local preview.
The production site is published only after the preview is reviewed and deployment
is authorized, following the repository's publishing workflow.

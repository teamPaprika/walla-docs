## 設定方法

<Steps>
  <Step>
    ### 埋め込みタブへ移動する
    編集画面右上の `⚙️` アイコンを押してフォーム設定を開き、左のタブ一覧から `埋め込み` を選びます。
  </Step>

  <Step>
    ### 埋め込み専用アクセスをオンにする
    `埋め込み専用アクセス` をオンにすると、3 つのモードから 1 つを選べます。

|モード|防げること|準備するもの|プラン|
|---|---|---|---|
|許可したサイトのみ|許可リスト外サイトでの埋め込み、リンクからの直接アクセス|許可 origin|Pro|
|ホスト署名トークン|上記 + ブラウザ以外からのリクエスト|許可 origin、署名シークレット、ホストサーバー連携|Enterprise|
|ホスト署名トークン + 会員識別|上記 + 会員単位の重複回答|上記 + トークンへの会員 ID の格納|Enterprise|

#### 1. 許可したサイトのみ

ブラウザ上で、許可外サイトの埋め込みと直接アクセスを防ぎます。設定がいちばん簡単です。
ただしサーバー間のリクエストは同じヘッダーを偽装できます。回答者が誰かを確認する必要がある場合は、下の署名モードをお使いください。

#### 2. ホスト署名トークン

サーバーが署名したトークンがないとフォームが開きません。ブラウザ以外でも同様です。ヘッダーの偽装では通過できません。

#### 3. ホスト署名トークン + 会員識別

トークンに含まれる会員 ID まで使って、重複回答を会員単位で防ぎます。
このモードを使うと、`回答者` タブの重複回答の要約に「外部会員 ID」も基準として表示されます。回答者に別途メールや電話番号の認証を求めなくても、1 会員につき 1 回だけ回答を受け取れます。
  </Step>
    <Step>
    ### 許可 origin を入力する
    フォームを埋め込むサイトのアドレスを入力します。

- スキームとホストだけを入力してください。`https://your-site.com`
- 末尾のスラッシュやパスは含めません。`https://your-site.com/survey` は誤った入力です。

<Callout type="warning" title="注意事項">
`許可したサイトのみ` モードは、origin を 1 つ以上追加しないとゲートが適用されません。空のままだと制限がかからないので必ず確認してください。
</Callout>

  </Step>
  <Step>
    ### 署名シークレットを発行する
    署名モードを選ぶと `署名シークレット` エリアが表示されます。ホストサーバーがトークンに署名するときに使う値です。

#### 1. 初めて発行するとき

`シークレットを発行` を押すと、シークレットの値が画面に一度だけ表示されます。すぐに `コピー` を押して、ホストサーバーの環境変数など安全な場所に保管してください。

<Callout type="warning" title="ご注意ください">
この値は二度と表示されません。コピーできなかった場合は再発行が必要で、再発行すると既存のトークンはただちに使えなくなります。
</Callout>

#### 2. 再発行するとき

すでにシークレットがある場合、ボタンは `シークレットを再発行` に変わります。押すと確認ウィンドウが表示されます。
再発行すると次のように動作します。

- 現在のシークレットで署名したトークンはただちに拒否されます。
- 埋め込みトークンに署名するすべてのホストを、新しいシークレットに差し替える必要があります。
- すでに開いているセッションは有効期限（最長 2 時間）まで維持されます。

ホストサーバーのデプロイ準備を終えてから再発行してください。順序が前後すると、その間は回答者がフォームを開けなくなります。
  </Step>

</Steps>


## ホストサーバー連携

署名モードでは、ホストサーバーが訪問者ごとに短い有効期間の JWT トークンを作り、埋め込みに渡す必要があります。

|用語|意味|
|---|---|
|**署名シークレット**|フォームごとに 1 つ発行される値です。ホストサーバーはこの値でトークンに署名します。|
|**トークン**|ホストサーバーが訪問者ごとに署名して作る、短い有効期間の JWT です。|

### 署名シークレットを保管する

コピーしたシークレットを、ホストサーバーの環境変数に保存します。

```bash
WALLA_EMBED_SECRET=ここにコピーした値
```

<Callout type="warning" title="注意事項">
署名シークレットをブラウザのバンドル、フロントエンドのコード、リポジトリに入れないでください。値が漏れると誰でもトークンを偽造できます。シークレットはフォームごとに異なるため、複数のフォームを埋め込む場合はフォームごとに別々に保管する必要があります。
</Callout>

### トークンに署名する

訪問者がページを開くたびに、サーバー側でトークンを新しく署名します。以下は `jose` を使った例です。

```js
import { SignJWT } from 'jose';

const secret = new TextEncoder().encode(process.env.WALLA_EMBED_SECRET);

const token = await new SignJWT({ email: user.email })
  .setProtectedHeader({ alg: 'HS256' })
  .setSubject(user.id)          // 会員識別モードでは必須
  .setAudience('{formId}')      // Walla のフォーム ID
  .setExpirationTime('5m')
  .sign(secret);
```

`ホスト署名トークン` モードでは `.setSubject(...)` は不要です。`ホスト署名トークン + 会員識別` モードでは、会員 ID を必ず `sub` に入れてください。

### トークンのルール

|項目|要件|
|---|---|
|`alg`|`HS256` のみ使用できます。|
|署名キー|署名シークレット文字列の UTF-8 バイトを使います。|
|`aud`|フォーム ID と一致する必要があります。配列の場合はフォーム ID を含めてください。|
|`exp`|必須で、最大 10 分後までしか許可されません。推奨する有効期間は 5 分です。|
|`sub`|会員識別モードでは必須で、255 文字以内である必要があります。|
|`email`|任意です。|
|エンコード|base64url 文字（`A-Za-z0-9_-`）を使います。|

## iframe にトークンを渡す

ダッシュボードの **共有 → 埋め込みコード** から、基本の埋め込みコードをコピーできます。

### 署名モード

トークンは URL フラグメント（`#`）で渡します。

```html
<iframe
  src="https://フォームのアドレス/f/{formId}#embedToken=署名したトークン"
  width="100%"
  height="500"
  style="border:0"
  loading="lazy">
</iframe>
```

<Callout type="warning" title="注意事項">
トークンをクエリ文字列（`?embedToken=`）で送らないでください。クエリ文字列はサーバーのアクセスログや Referer ヘッダーに残る可能性があります。必ずフラグメント（`#embedToken=`）を使ってください。
</Callout>

### 許可したサイトのみモード

このモードにトークンは不要です。

```html
<iframe
  src="https://フォームのアドレス/f/{formId}"
  width="100%"
  height="500"
  style="border:0"
  loading="lazy">
</iframe>
```

許可 origin には `https://your-site.com` のようにスキームとホストだけを入力します。末尾のスラッシュやパスは入れないでください。

### 通過後のセッション

ゲートを一度通過すると、その結果が 2 時間維持されます。この間、回答者は新しいトークンなしで画面を再読み込みできます。

## 連携の流れ

署名モードでは、次の順序でフォームが開きます。

1. ユーザーが自社サービスにログインしているか確認します。
2. 発行された署名シークレットでトークンに署名します。会員識別モードなら、トークンに会員 ID も入れます。
3. 署名したトークンを URL フラグメントに乗せてフォームを開きます。
4. Walla がトークンの署名と origin を検証してから、フォームを表示します。

## トラブルシューティング

<Accordions>
  <Accordion title="許可したサイトなのにフォームが開きません">
    **原因** 許可 origin にパスや末尾のスラッシュが含まれています。**解決方法** スキームとホストだけを残して保存し直してください。
  </Accordion>

  <Accordion title="制限がかかっていないようです">
    **原因** `許可したサイトのみ` モードなのに、許可 origin が空です。**解決方法** origin を 1 つ以上登録してください。
  </Accordion>

  <Accordion title="シークレットを再発行したら急にブロックされました">
    **原因** ホストサーバーがまだ以前のシークレットで署名しています。**解決方法** ホストのシークレットを新しい値に差し替えて再デプロイしてください。すでに開いていたセッションは最長 2 時間維持されるため、その時間を過ぎるとすべてのアクセスがブロックされます。
  </Accordion>

  <Accordion title="トークンを送っているのに拒否され続けます">
    トークンがクエリ文字列にある、期限切れ、署名や `aud` の値が正しくない、といった可能性があります。トークンをフラグメント（`#embedToken=`）で渡しているか確認し、ホストサーバーの署名シークレット、`aud`、`exp` を点検してください。
  </Accordion>

  <Accordion title="会員 ID が重複回答の判定に反映されません">
    モードが `ホスト署名トークン` になっていないか確認してください。会員単位で重複回答を制限するには、`ホスト署名トークン + 会員識別` モードを使い、トークンの `sub` に会員 ID を入れる必要があります。
  </Accordion>

  <Accordion title="再発行したのに以前の会員情報で回答されます">
    すでに開いているセッションが残っている可能性があります。ゲートを通過したセッションは最長 2 時間維持されます。2 時間後に新しいトークンで再度確認してください。
  </Accordion>
</Accordions>

<Callout title="こんなときに使います">
- 社内ポータルや会員ページにフォームを埋め込んでいて、リンクが外部に漏れるのを防ぎたいとき
- 自社サービスの会員だけが回答できるようにしたいとき
- 会員 1 人につき 1 回だけ回答させたいが、メール認証を別途させるのは手間なとき
</Callout>

## カスタム Webhook を作成する

自動化を作成したあと詳細編集画面へ移動すると、より細かい設定ができます。
<Steps>
  <Step>
    ### 連携ページに入る
    プロジェクト編集画面上部の `連携する` をクリックします。

  </Step>
  <Step>
    ### 新しい自動化を追加する
    「マイ自動化」セクションで `新しい自動化` ボタンをクリックして始めます。

  </Step>
  <Step>
    ### 作成する
    ポップアップで自動化の名前などの情報を入力し、トリガータイプを選んでから `作成` をクリックします。
	    - **自動化の名前**: 自動化を区別するための名前です。
	    - **トリガータイプ**: フォーム送信時／回答者の不適格など、自動化を作動させる条件を指します。トリガータイプは作成後に変更できません。

  </Step>
  <Step>
    ### 経路設定（ロジック）
    特定の条件（選択式の答えが A のとき、短文の回答に B が含まれるときなど）に応じて通知が届くよう、フィルターをかけられます。
	    - 右上の `+` を押すと複数の経路を作成できます。このとき、各経路に自動化モジュールを個別に接続しないと、デフォルト経路（すべての回答送信に対する通知）として動作します。
	    - 各経路の下部にある `+ 条件を追加` を押すと、複合的な条件を設定できます。

  </Step>
  <Step>
    ### Webhook アドレスを入力する
    **Webhook アドレス**: データを受け取るサーバーのアドレスです。

  </Step>
  <Step>
    ### Webhook の送信フォーマットを指定する
	    自動（デフォルトの Webhook Body）で送るか、カスタム Body を指定するかを選びます。自動を選んだ場合は保存後すぐに有効化して利用でき、カスタム Body を選んだ場合は次のステップへ進みます。
	    - **自動（デフォルト）**: フォームの回答データが自動的にペイロードへ含まれます。`プレビュー` を開くと、実際に送信されるペイロードの形を事前に確認できます。
	    - **カスタム**: リクエストの種類、Headers、Body を自分で指定します。

  </Step>
  <Step>
    ### リクエストの種類と Headers を設定する
	    - **リクエストの種類**: POST / GET / PUT など
	    - **Headers の設定**: `Content-Type`、認証トークンなどを必要に応じて追加

  </Step>
    <Step>
    ### Body を編集する
	    送信されるメッセージの文言を自由に修正したり、回答値（`{{responseKey}}`）を変数として挿入したりできます。

  </Step>
    <Step>
    ### 認証方式を設定する（任意）
    Webhook の利用時に `Bearer Token`、`Basic Auth`、`API Key` などのセキュリティ認証方式を選べます。

  </Step>
    <Step>
    ### 隠しフィールドの値を含める設定（任意）
	    詳細設定の `隠しフィールドの値を含める` をオンにすると、[トラッキング（隠しフィールド）](/ja/docs/help-center/share-forms/tracking-hidden-fields)で収集した値も Webhook の送信データに含まれます。流入経路や顧客グループなどのトラッキング情報を外部サービスへ渡したいときにお使いください。オフにすると、隠しフィールドを除いた回答値だけが送信されます。

  </Step>
    <Step>
    ### 変更を保存して有効化する
    変更を保存し、有効化を押してはじめて Webhook が実際に動作します。

  </Step>
</Steps>
## Slack 連携 - 回答送信時に Slack 通知

<Steps>
 <Step>
    ### Create New App をクリックする
    [https://api.slack.com/apps](https://api.slack.com/apps) で「Create New App」をクリックします。

  </Step>
  <Step>
    ### From scratch を選ぶ
    「From scratch」を選択します。

  </Step>
  <Step>
    ### App 名とワークスペースを設定する
    「App Name」に App の名前を入力し、どのワークスペースで動作させるかを選びます。

  </Step>
  <Step>
    ### Incoming Webhooks を有効にする
    「Incoming Webhooks」を有効にしてから「Add New Webhook」をクリックします。

  </Step>
  <Step>
    ### チャンネルを選ぶ
    ワークスペース内で Webhook を適用するチャンネルを選択します。

  </Step>
  <Step>
    ### Webhook URL をコピーする
    「Install App」で Webhook URL をコピーします。

  </Step>
<Step>
    ### 連携ページに入る
    プロジェクト編集画面上部の `連携する` をクリックします。

  </Step>
  <Step>
    ### 新しい Slack 自動化を追加する
    「マイ自動化」セクションで `Slack` ボタンをクリックして始めます。

  </Step>
  <Step>
    ### 作成する

	    - **Webhook URL**: データを受け取る Slack サーバーのアドレスです。Slack Webhook URL の設定方法は[こちら](https://docs.slack.dev/messaging/sending-messages-using-incoming-webhooks/)で確認できます。
	    - **Body Preset**: Webhook 通知が Slack でどのような形で届くかを指定します。

## Gmail 連携 - 回答送信時にメール送信

<Steps>
  <Step>
    ### 連携ページに入る
    プロジェクト編集画面上部の `連携する` をクリックします。

  </Step>
  <Step>
    ### 新しい自動化を追加する
    「マイ自動化」セクションで `Gmail` ボタンをクリックして始めます。

  </Step>
  <Step>
    ### 作成する
    ポップアップで自動化の名前などの情報を入力し、トリガータイプを選んでから `作成` をクリックします。
	    - **自動化の名前**: 自動化を区別するための名前です。
	    - **トリガータイプ**: フォーム送信時／回答者の不適格など、自動化を作動させる条件を指します。トリガータイプは作成後に変更できません。
	    - **送信者**: Gmail を送信する Google アカウントです。すでにワークスペースに連携済みのアカウントを選ぶか、新しい Google アカウントにログインします。

  </Step>
  <Step>
    ### 経路設定（ロジック）
    特定の条件（選択式の答えが A のとき、短文の回答に B が含まれるときなど）に応じて通知が届くよう、フィルターをかけられます。
	    - 右上の `+` を押すと複数の経路を作成できます。このとき、各経路に自動化モジュールを個別に接続しないと、デフォルト経路（すべての回答送信に対する通知）として動作します。
	    - 各経路の下部にある `+ 条件を追加` を押すと、複合的な条件を設定できます。

  </Step>
  <Step>
    ### 送信者を指定する
	    Gmail を送信する Google アカウントを選び、送信者名を入力します。

  </Step>
  <Step>
    ### 受信者を指定する
	    - メールを受信するアカウントを入力します。
	    - メールアドレスを直接入力するか、値の参照（@）を使って動的に設定できます。
	    - 複数のメールアドレスを追加するときは、カンマ（,）、スペース、または Enter キーで区切ってください。
	    - responseKey や timestamp など、一部の事前定義された参照値はメールアドレスとして使えません。
	    - メールアドレスのフィールドを参照値として使うことをおすすめします。メールの形式が正しくない場合、送信に失敗することがあります。

  </Step>
    <Step>
    ### CC・BCC・返信先メールを指定する
	    - メールを CC／BCC で受信するアカウント、または返信先のアカウントを入力します。
	    - メールアドレスを直接入力するか、値の参照（@）を使って動的に設定できます。
	    - 複数のメールアドレスを追加するときは、カンマ（,）、スペース、または Enter キーで区切ってください。
	    - responseKey や timestamp など、一部の事前定義された参照値はメールアドレスとして使えません。

  </Step>
    <Step>
    ### 隠しフィールドの値を含める設定（任意）
	    詳細設定の `隠しフィールドの値を含める` をオンにすると、[トラッキング（隠しフィールド）](/ja/docs/help-center/share-forms/tracking-hidden-fields)で収集した値もメールに含まれます。オフにすると、隠しフィールドを除いた回答値だけが使われます。
	    <Callout type="warning" title="注意事項">
    隠しフィールドには、流入経路や顧客識別子のように回答者が直接入力していない値が入ることがあります。回答者など外部の受信者に送るメールであれば、どんな値が一緒に渡されるかを確認してから有効にしてください。
    </Callout>
    

    
  </Step>
    <Step>
    ### 変更を保存して有効化する
    変更を保存し、有効化を押してはじめて Webhook が実際に動作します。

  </Step>
</Steps>

## Webhook をテストする

Webhook を有効にする前に、テスト送信で正常に動作するか確認できます。

### 1. 既存の回答でテストする
- `テスト` ボタンの横にある `下向き矢印` アイコンを押すと、すでに送信された回答値で Webhook をテストできます。テストに使う回答を選んでから `テストを実行` をクリックしてください。
<Callout type="warning" title="注意事項">
Gmail 自動化の受信者にメールアドレスのフィールドを指定している場合は、受信を正確に確認するため、既存の回答でテストすることをおすすめします。
</Callout>


### 2. ランダムな値でテストする
- まだ送信された回答がない場合は、`テスト` ボタンを押してランダムな値で Webhook をテストできます。

## Webhook を再送信する（Webhook の送信に失敗した場合）


- Webhook の送信に失敗した場合は、再送信できます。
- エラーの要約から、どんな理由で送信に失敗したかを確認できます。
	- たとえば Gmail 自動化で「At least one 'to' recipient is required」と表示される場合は、受信者を入力していないため送信できない状態を意味します。
	- 「Webhook failed with status: 400」と表示される場合は、Webhook サーバーがリクエストを受け取ったものの「不正なリクエスト（Bad Request）」として拒否したという意味で、送ったデータの形式が正しくないためにエラーが発生したことを表します。
### 再送信の方法
- **元の設定で再試行**: 実行時に保存された元の設定で再送信します。設定を変えずに同じ条件でもう一度試したいときに便利です。一時的なサーバーエラーによる送信失敗なら、まず元の設定で再試行してみてください。
- **現在の設定で再送信**: 現在保存されている自動化設定で再送信します。設定を修正して保存したあとに再度試すときに便利です。受信者を入力していない、データ形式が正しくないなどが原因のエラーなら、その内容を修正してから現在の設定で再送信をクリックしてください。

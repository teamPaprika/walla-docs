# 認証

Walla Open API は API キーまたは OAuth アクセストークンで認証します。すべての API リクエストには、どちらか一方をヘッダーに含める必要があります。OAuth トークンは一部の読み取り操作と回答ファイルのダウンロードにのみ使用できます。

## 認証方式の選択

| 項目 | API キー | OAuth アクセストークン |
|------|----------|------------------------|
| ヘッダー | `X-WALLA-API-KEY: <API キー>` | `Authorization: Bearer <アクセストークン>` |
| チームの範囲 | キーが発行されたチーム（チームの指定は不要） | トークンのユーザーが所属するチーム。`GET /workspaces`・`GET /forms` には `teamId` が必要（[チームの指定](#チームの指定)） |
| 利用できる操作 | すべての Open API 操作 | 読み取り操作と回答ファイルのダウンロードのみ（[スコープと利用できる操作](#スコープと利用できる操作)） |
| 権限 | API キーに紐づく権限 | トークンのユーザーのチームメンバーシップ・ワークスペースへのアクセス・回答の閲覧・ファイルのダウンロード権限 |
| レート制限 | API キーあたり 1 時間 6,000 件 | プランごとのチーム単位の 1 時間あたりの上限（[OAuth トークンの呼び出し上限](#oauth-トークンの呼び出し上限)） |
| 適したケース | チーム単位のサーバー連携、回答の検索・エクスポート・送信・書き込み操作 | ユーザーの権限の範囲内でデータを読み取るアプリ |

2 つのヘッダーを同時に送ると、API キーが優先されます。既存の API キー連携はこれまでどおり動作します。

## API キー認証

すべてのリクエストの `X-WALLA-API-KEY` ヘッダーに API キーを含めてください。

### ヘッダーの形式

```
X-WALLA-API-KEY: your_api_key_here
```

### チームスコープの API キー

Walla の API キーは **チーム単位** で生成されます。

- 各 API キーは特定のチームに紐づきます
- チーム情報はすべてのリクエストに自動的に含まれます
- API 呼び出し時に別途チーム情報を渡す必要はありません
- ワークスペース、フォーム、回答は自動的にそのチームの範囲で絞り込まれます

## API キーを発行する

1. [app.walla.my](https://app.walla.my) にログインします
2. [app.walla.my/open-api/doc](https://app.walla.my/open-api/doc) へ移動します
3. ページ上部の API キーのセクションでキーを生成またはコピーします

> **重要**: API キーはパスワードと同様に安全に保管し、外部に共有しないでください。

## 認証済みリクエストを送る

各言語で API キーを含める方法は次のとおりです。

### cURL

```bash
curl -X GET "https://api.walla.my/open-api/v1/workspaces" \
  -H "X-WALLA-API-KEY: your_api_key_here" \
  -H "Content-Type: application/json"
```

### JavaScript (Fetch)

```javascript
fetch('https://api.walla.my/open-api/v1/workspaces', {
  method: 'GET',
  headers: {
    'X-WALLA-API-KEY': 'your_api_key_here',
    'Content-Type': 'application/json'
  }
})
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('エラー:', error));
```

### Python (requests)

```python
import requests

url = "https://api.walla.my/open-api/v1/workspaces"
headers = {
    "X-WALLA-API-KEY": "your_api_key_here",
    "Content-Type": "application/json"
}

response = requests.get(url, headers=headers)
data = response.json()
print(data)
```

### Node.js (axios)

```javascript
const axios = require('axios');

const config = {
  headers: {
    'X-WALLA-API-KEY': 'your_api_key_here',
    'Content-Type': 'application/json'
  }
};

axios.get('https://api.walla.my/open-api/v1/workspaces', config)
  .then(response => console.log(response.data))
  .catch(error => console.error('エラー:', error));
```

## OAuth アクセストークン

OAuth アクセストークンは `Authorization: Bearer <アクセストークン>` ヘッダーで送ります。パスとレスポンスの形式は API キーでの呼び出しと同じです。ただし、呼び出せるのは下の表の操作のみです。

### トークンの取得

トークンは OAuth の authorization code フローで取得します。リクエストの際は次の点を守ってください。

- `openid` スコープを必ず一緒にリクエストしてください。含まれていないと、すべての呼び出しが `401` になり、トークンを更新しても解決しません。
- 使用する操作に合ったスコープ（`project:read`、`project:response.read`、`project:response.download`）をリクエストしてください。
- トークンを更新するには `offline_access` もリクエストしてください。含まれていないと refresh トークンは発行されません。
- `resource` パラメーター（RFC 8707）は送らないでください。送ると、そのトークンによるすべての呼び出しが `403 insufficient_scope` になります。

一部のデプロイ環境（例: オンプレミス）では、新しいトークンの発行・更新が停止されている場合があります。その場合でも、すでに発行済みのトークンは有効期限が切れるか取り消されるまで使用できます。

### スコープと利用できる操作

パスは `/open-api/v1` を基準とします。

| スコープ | 利用できる操作 |
|----------|----------------|
| `project:read` | `GET /teams`<br />`GET /workspaces`, `GET /workspaces/{workspaceId}`, `GET /workspaces/{workspaceId}/forms`<br />`GET /forms`, `GET /forms/{formId}`<br />`GET /forms/{formId}/fields`, `GET /forms/{formId}/fields/{fieldId}`, `GET /forms/{formId}/fields/{fieldId}/description`<br />`GET /forms/{formId}/hidden-fields`<br />`POST /forms/{formId}/exports/field-definitions`<br />`GET /field-output-schemas` |
| `project:response.read` | `GET /forms/{formId}/responses` |
| `project:response.download` | `POST /forms/{formId}/responses/{responseId}/fields/{fieldId}/file`（[回答ファイルのダウンロード](/en/docs/developer-docs/responses#download-a-response-file)） |

**API キー専用の操作**: 次の操作を OAuth トークンで呼び出すと `403 This endpoint does not accept OAuth tokens` が返されます。

- 特定の回答の取得 `GET /forms/{formId}/responses/{responseId}`
- 回答の検索 `POST /forms/{formId}/responses/search`
- 回答のエクスポート `POST /forms/{formId}/exports/responses`
- フォームの送信（`/forms/{formId}/delivery` 以下のすべての操作）
- 隠しフィールドの追加 `POST`・削除 `DELETE`

### チームの指定

OAuth トークンで `GET /workspaces` または `GET /forms` を呼び出すときは、`teamId` クエリパラメーターが必要です。含まれていないと `400` が返されます。API キーでの呼び出しでは `teamId` は無視されます。

チーム ID は [`GET /teams`](/en/docs/developer-docs/workspaces#list-teams) で確認してください。トークンで呼び出すと、トークンのユーザーが所属するチームのうち、Open API の利用設定と IP アクセス制限を通過したチームのみが返されます。

```json
{
  "success": true,
  "data": [
    { "id": "team_456", "name": "マーケティングチーム", "profileUrl": null }
  ]
}
```

- 2 段階認証を有効にしていないゲストにもチームは一覧に表示されますが、そのチームの操作は `403` を返します。
- トークンで `GET /workspaces/{workspaceId}` を呼び出したとき、トークンのユーザーがそのワークスペースにアクセスできない場合は `403 {"error":"Access denied"}` が返されます。

### cURL の例

以下の例では、発行済みのアクセストークンを環境変数 `WALLA_OAUTH_TOKEN` に保存していると仮定します。

```bash
# 1. 呼び出し可能なチームの取得 (project:read)
curl -X GET "https://api.walla.my/open-api/v1/teams" \
  -H "Authorization: Bearer $WALLA_OAUTH_TOKEN"

# 2. チームのワークスペースの取得 (project:read、teamId 必須)
curl -X GET "https://api.walla.my/open-api/v1/workspaces?teamId=team_456" \
  -H "Authorization: Bearer $WALLA_OAUTH_TOKEN"

# 3. フォームの回答一覧の取得 (project:response.read)
curl -X GET "https://api.walla.my/open-api/v1/forms/form_abc/responses" \
  -H "Authorization: Bearer $WALLA_OAUTH_TOKEN"
```

回答ファイルのダウンロード例は [回答ファイルのダウンロード](/en/docs/developer-docs/responses#download-a-response-file) を参照してください。

## 認証エラー

認証に失敗すると、以下のようなエラーが返されます。

### 401 Unauthorized

次の場合に発生します。
- リクエストに API キーが含まれていない場合
- API キーが無効、または期限切れ・取り消し済みの場合

**レスポンス例:**

```json
{
  "error": "Unauthorized"
}
```

### 403 Forbidden

認証は通過したものの、そのリソースにアクセスする権限がない場合に発生します。

**レスポンス例:**

```json
{
  "error": "Forbidden"
}
```

### OAuth トークンのエラー

- **401**: トークンが無効、または期限切れです。レスポンスに `WWW-Authenticate: Bearer error="invalid_token"` ヘッダーが含まれます。トークンを更新すべきなのはこの場合だけです。
- **403 `insufficient_scope`**: トークンに必要なスコープがありません。本文は `{"error":"insufficient_scope","scope":"<必要なスコープ>"}` です。
- **403 `This endpoint does not accept OAuth tokens`**: [API キー専用の操作](#スコープと利用できる操作)です。API キーで呼び出してください。
- **403 `Forbidden`**: チームメンバーではない、2 段階認証を有効にしていないゲストである、またはアクセスできないワークスペース ID です。
- **403 `Unauthorized`**: サーバーがトークンを確認できませんでした。トークンが無効という意味ではないため、更新せずにしばらくしてから再試行してください。

すべてのエラーの一覧は [エラーコード](/ja/docs/developer-docs/error-codes) を参照してください。

## ベストプラクティス

### セキュリティ

- **API キーをコミットしない** - Git などのバージョン管理システムに API キーを含めないでください
- **環境変数を使う** - API キーは環境変数で管理してください
- **キーを定期的に交換する** - セキュリティのため、定期的にキーを更新してください
- **環境ごとにキーを分ける** - 開発・ステージング・本番でそれぞれ別のキーを使ってください

### 環境変数

API キーを環境変数に保存してください。

```bash
# .env ファイル
WALLA_API_KEY=your_api_key_here
```

コードからは以下のように読み込めます。

```javascript
// JavaScript
const apiKey = process.env.WALLA_API_KEY;
```

```python
# Python
import os
api_key = os.getenv('WALLA_API_KEY')
```

### レート制限

Walla Open API には、システムの安定性のためレート制限が適用されます。

- **制限**: API キーあたり 1 時間 6,000 件
- **時間ウィンドウ**: 1 時間（ローリングウィンドウ）

レート制限を超えると `429 Too Many Requests` が返されます。その場合は:

- 指数バックオフで再試行してください
- 可能ならレスポンスをキャッシュしてください
- 不要な重複リクエストを減らしてください
- API の使用量をモニタリングしてください
- 可能ならリクエストをまとめて処理してください

上記の制限は API キーでの呼び出しに適用されます。

#### OAuth トークンの呼び出し上限

OAuth トークンでの呼び出しは、API キーの 1 時間 6,000 件の制限とは別に集計され、すべてのプランで利用できます。プランが決めるのは上限のみです。1 つのチームの上限を、そのチームのすべてのユーザーとアプリで共有します。

| 対象 | 1 時間あたりの上限 |
|------|--------------------|
| Free プランのチーム | 600 件 |
| Pro プランのチーム | 3,000 件 |
| Enterprise・カスタムプランのチーム | 6,000 件 |
| `GET /teams`、`GET /field-output-schemas` | ユーザーあたり 600 件 |

- 1 時間のウィンドウは、そのチーム（またはユーザー）の最初の呼び出しから始まります。
- 上限を超えると `429 {"error":"rate_limit_exceeded"}` が返され、`Retry-After`（秒）、`RateLimit-Limit`、`RateLimit-Remaining`、`RateLimit-Reset` ヘッダーが含まれます。`Retry-After` の分だけ待ってから再試行してください。
- 上限を超えた後に送った呼び出しも回数に含まれます。
- チームの Open API の利用設定と IP アクセス制限は、プランに関係なく適用されます。

## トラブルシューティング

### よくある問題

**問題**: API キーを入れているのに 401 エラーが発生する

**解決方法**:
- API キーが正しく、期限切れでないか確認してください
- そのワークスペースに対する権限があるか確認してください
- ヘッダー名が正確に `X-WALLA-API-KEY` か確認してください（大文字・小文字を区別）
- アクセス権限のあるワークスペースのリソースか確認してください

**問題**: API キーが送信されていない

**解決方法**:
- ヘッダーの形式が正しいか確認してください
- HTTP クライアントでカスタムヘッダーが含まれているか確認してください
- ヘッダー名に打ち間違いがないか確認してください

**問題**: OAuth トークンで `GET /workspaces` または `GET /forms` を呼び出すと 400 エラーが発生する

**解決方法**:
- `teamId` クエリパラメーターを含めてください。チーム ID は `GET /teams` で確認できます

**問題**: OAuth トークンでの呼び出しが 403 エラーを返す

**解決方法**:
- `insufficient_scope` の場合は、必要なスコープをリクエストしたか、トークンのリクエストで `resource` パラメーターを送っていないか確認してください
- `This endpoint does not accept OAuth tokens` の場合は、API キーで呼び出してください
- `Unauthorized` の場合は、トークンを更新せずにしばらくしてから再試行してください

## 追加のセキュリティ上の考慮点

### API キーの保護

1. **コードにハードコーディングしない**
   - ソースコードに API キーを直接書かないでください
   - 環境変数やシークレット管理サービスを使ってください

2. **HTTPS のみを使う**
   - API は HTTPS でのみアクセスできます
   - HTTP リクエストは拒否されます

3. **キーの流出を監視する**
   - 公開リポジトリにキーが上がっていないか定期的に確認してください
   - キーが流出した場合はただちに破棄し、新しく発行してください

### 権限の管理

- API キーはワークスペースの権限と連動します
- チームメンバーごとに個別の API キーを発行してください
- 使わなくなったキーはすぐに破棄してください
- API キーの利用状況を定期的に点検してください
- OAuth トークンでの呼び出しには、トークンのユーザーのチームメンバーシップ、ワークスペースへのアクセス権限、回答の閲覧・ファイルのダウンロード権限が適用されます

### エラー処理のベストプラクティス

```javascript
async function makeAuthenticatedRequest(url) {
  try {
    const response = await fetch(url, {
      headers: {
        'X-WALLA-API-KEY': process.env.WALLA_API_KEY,
        'Content-Type': 'application/json'
      }
    });

    if (response.status === 401) {
      console.error('認証に失敗しました: API キーを確認してください');
      // ユーザーに通知するか、再認証のプロセスを開始する
      return null;
    }

    if (!response.ok) {
      throw new Error(`HTTP エラー! ステータス: ${response.status}`);
    }

    return await response.json();
  } catch (error) {
    console.error('リクエスト失敗:', error);
    throw error;
  }
}
```

```python
import requests
import os

def make_authenticated_request(url):
    headers = {
        'X-WALLA-API-KEY': os.getenv('WALLA_API_KEY'),
        'Content-Type': 'application/json'
    }

    try:
        response = requests.get(url, headers=headers)

        if response.status_code == 401:
            print('認証に失敗しました: API キーを確認してください')
            return None

        response.raise_for_status()
        return response.json()

    except requests.RequestException as e:
        print(f'リクエスト失敗: {e}')
        raise
```

## 建立自訂 Webhook

建立自動化後前往詳細編輯畫面，就能做更細緻的設定。
<Steps>
  <Step>
    ### 進入整合頁面
    點選專案編輯畫面上方的 `整合`。

  </Step>
  <Step>
    ### 新增自動化
    在「我的自動化」區塊點選 `新增自動化` 按鈕開始。

  </Step>
  <Step>
    ### 建立
    在彈出視窗輸入自動化名稱等資訊，選擇觸發類型後點選 `建立`。
	    - **自動化名稱**：用來區分自動化的名稱。
	    - **觸發類型**：指表單送出時／填答者遭淘汰等會啟動自動化的條件，觸發類型在建立後就無法變更。

  </Step>
  <Step>
    ### 設定路徑（邏輯）
    可以依特定條件（選擇題答案為 A 時、簡答回覆中含有 B 時等）加上篩選，決定通知何時送出。
	    - 點選右上角的 `+` 可以建立多條路徑。此時若沒有為各條路徑分別連接自動化模組，就會以預設路徑（對所有回覆送出通知）運作。
	    - 點選各路徑下方的 `+ 新增條件`，可以設定複合條件。

  </Step>
  <Step>
    ### 輸入 Webhook 網址
    **Webhook 網址**：接收資料的伺服器位址。

  </Step>
  <Step>
    ### 指定 Webhook 傳送格式
	    選擇要以自動（預設 Webhook Body）傳送，還是自訂 Body。選擇自動時，儲存後即可直接啟用使用；選擇自訂 Body 時，則進入下一個步驟。
	    - **自動（預設）**：表單回覆資料會自動包含在 payload 中。開啟 `預覽` 就能事先確認實際會傳送的 payload 形式。
	    - **自訂**：自行指定請求類型、Headers 與 Body。

  </Step>
  <Step>
    ### 設定請求類型與 Headers
	    - **請求類型**：POST / GET / PUT 等
	    - **Headers 設定**：視需要加上 `Content-Type`、驗證權杖等

  </Step>
    <Step>
    ### 編輯 Body
	    可以自由修改要傳送的訊息內容，或把回覆值（`{{responseKey}}`）當作變數插入。

  </Step>
    <Step>
    ### 設定驗證方式（選填）
    使用 Webhook 時，可以選擇 `Bearer Token`、`Basic Auth`、`API Key` 等安全驗證方式。

  </Step>
    <Step>
    ### 設定是否包含隱藏欄位值（選填）
	    開啟進階設定中的 `包含隱藏欄位值` 後，透過[追蹤（隱藏欄位）](/zh-TW/docs/help-center/share-forms/tracking-hidden-fields)收集到的值也會一併包含在 Webhook 傳送的資料中。需要把來源管道、顧客族群等追蹤資訊傳給外部服務時可以使用。關閉時只會傳送不含隱藏欄位的回覆值。

  </Step>
    <Step>
    ### 儲存變更並啟用
    必須儲存變更並點選啟用，Webhook 才會實際運作。

  </Step>
</Steps>
## Slack 整合 - 回覆送出時發送 Slack 通知

<Steps>
 <Step>
    ### 點選 Create New App
    在 [https://api.slack.com/apps](https://api.slack.com/apps) 點選「Create New App」。

  </Step>
  <Step>
    ### 選擇 From scratch
    選擇「From scratch」。

  </Step>
  <Step>
    ### 設定 App 名稱與工作區
    在「App Name」輸入 App 名稱，並選擇要在哪個工作區運作。

  </Step>
  <Step>
    ### 啟用 Incoming Webhooks
    啟用「Incoming Webhooks」後點選「Add New Webhook」。

  </Step>
  <Step>
    ### 選擇頻道
    在工作區中選擇要套用 Webhook 的頻道。

  </Step>
  <Step>
    ### 複製 Webhook URL
    在「Install App」中複製 Webhook URL。

  </Step>
<Step>
    ### 進入整合頁面
    點選專案編輯畫面上方的 `整合`。

  </Step>
  <Step>

  </Step>

	    - **寄件者**：用來寄送 Gmail 的 Google 帳號。你可以選擇已整合到工作區的帳號，或登入新的 Google 帳號。

  </Step>
  <Step>
    ### 設定路徑（邏輯）
    可以依特定條件（選擇題答案為 A 時、簡答回覆中含有 B 時等）加上篩選，決定通知何時送出。

	    - 點選各路徑下方的 `+ 新增條件`，可以設定複合條件。

  </Step>
  <Step>
    ### 指定寄件者
	    選擇要用來寄送 Gmail 的 Google 帳號，並輸入寄件者名稱。

  </Step>
  <Step>
    ### 指定收件者
	    - 輸入要接收郵件的帳號。
	    - 可以直接輸入電子郵件，或使用值參照（@）動態設定。
	    - 要加入多個電子郵件時，請用逗號（,）、空格或 Enter 鍵分隔。
	    - responseKey、timestamp 等部分預先定義的參照值無法當作電子郵件使用。
	    - 建議使用電子郵件欄位作為參照值。若電子郵件格式不正確，可能會傳送失敗。

  </Step>
    <Step>
    ### 指定副本、密件副本與回覆信箱
	    - 輸入要以副本／密件副本接收郵件或回覆的帳號。
	    - 可以直接輸入電子郵件，或使用值參照（@）動態設定。
	    - 要加入多個電子郵件時，請用逗號（,）、空格或 Enter 鍵分隔。
	    - responseKey、timestamp 等部分預先定義的參照值無法當作電子郵件使用。

## 測試 Webhook

啟用 Webhook 之前，可以先用測試發送確認 Webhook 是否正常運作。

### 1. 用既有回覆測試
- 點選 `測試` 按鈕旁的 `向下箭頭` 圖示，就能用已送出的回覆值測試 Webhook。選擇要用來測試的回覆後，點選 `執行測試`。
<Callout type="warning" title="注意事項">
若在 Gmail 自動化的收件者中填入了電子郵件欄位，建議用既有回覆測試，才能準確確認收件狀況。
</Callout>


### 2. 用隨機值測試
- 若還沒有任何已送出的回覆，可以點選 `測試` 按鈕，用隨機值測試 Webhook。

## 重新發送 Webhook（Webhook 發送失敗時）


- Webhook 發送失敗時可以重新發送。
- 你可以從錯誤摘要中確認發送失敗的原因。
	- 舉例來說，Gmail 自動化中顯示「At least one 'to' recipient is required」時，代表因為沒有填寫收件者而無法發送。
	- 顯示「Webhook failed with status: 400」時，代表 Webhook 伺服器收到了請求，但判定為「錯誤的請求（Bad Request）」而拒絕，也就是傳送的資料格式不正確導致錯誤。
### 重新發送的方式
- **以原始設定重試**：使用執行當下儲存的原始設定重新發送。想在不變更設定的情況下用相同條件再試一次時很好用。若失敗是暫時性的伺服器錯誤造成，請先用原始設定重試。
- **以目前設定重新發送**：使用目前儲存的自動化設定重新發送。修正設定並儲存後想再試一次時很好用。若錯誤是因為沒有填寫收件者或資料格式輸入不正確造成，請先修正該內容，再點選以目前設定重新發送。

## 設定方式

<Steps>
  <Step>
    ### 前往嵌入分頁
    點選編輯畫面右上角的 `⚙️` 圖示開啟問卷設定，然後在左側分頁清單選擇 `嵌入`。
  </Step>

  <Step>
    ### 開啟僅限嵌入存取
    開啟 `僅限嵌入存取` 後，可以從三種模式中擇一。

|模式|能擋下什麼|需要準備什麼|方案|
|---|---|---|---|
|僅限允許的網站|允許清單外網站的嵌入、直接以連結進入|允許的 origin|Pro|
|主機簽章權杖|上述 + 非瀏覽器發出的請求|允許的 origin、簽章密鑰、主機伺服器串接|Enterprise|
|主機簽章權杖 + 會員識別|上述 + 以會員為單位的重複回覆|上述 + 在權杖中帶入會員 ID|Enterprise|

#### 1. 僅限允許的網站

在瀏覽器端擋下非允許網站的嵌入與直接進入。設定最為簡單。
但伺服器對伺服器的請求可以偽裝出相同的標頭。若需要確認填答者身分，請使用下方的簽章模式。

#### 2. 主機簽章權杖

必須有伺服器簽章過的權杖才能開啟表單，非瀏覽器的請求也一樣。單純偽裝標頭無法通過。

#### 3. 主機簽章權杖 + 會員識別

進一步用權杖中帶的會員 ID，以會員為單位擋下重複回覆。
使用這個模式時，`填答者` 分頁的重複回覆摘要也會一併把「外部會員 ID」列為判定基準。不必要求填答者另外做電子郵件或電話號碼驗證，就能讓每位會員只作答一次。
  </Step>
    <Step>
    ### 輸入允許的 origin
    輸入要嵌入問卷的網站位址。

- 只填通訊協定與主機名稱。`https://your-site.com`
- 不要加上結尾斜線或路徑。`https://your-site.com/survey` 是錯誤的輸入。

<Callout type="warning" title="注意事項">
`僅限允許的網站` 模式必須至少新增一個 origin，閘道才會生效。清單為空時不會有任何限制，請務必確認。
</Callout>

  </Step>
  <Step>
    ### 發行簽章密鑰
    選擇簽章模式後會出現 `簽章密鑰` 區塊。這是主機伺服器為權杖簽章時使用的值。

#### 1. 第一次發行時

點選 `發行密鑰` 後，密鑰的值只會顯示一次。請立刻點選 `複製`，並保存在主機伺服器的環境變數等安全之處。

<Callout type="warning" title="請特別注意">
這個值不會再次顯示。若沒有複製到就必須重新發行，而重新發行後既有的權杖會立即失效。
</Callout>

#### 2. 重新發行時

若已有密鑰，按鈕會變成 `重新發行密鑰`。點選後會出現確認視窗。
重新發行後的行為如下。

- 以目前密鑰簽章的權杖會立即被拒絕。
- 所有簽章嵌入權杖的主機都必須更換成新密鑰。
- 已開啟的工作階段會維持到到期為止（最長 2 小時）。

請在主機伺服器部署準備就緒後再重新發行。順序顛倒的話，這段期間填答者將無法開啟表單。
  </Step>

</Steps>


## 主機伺服器串接

在簽章模式下，主機伺服器必須為每位訪客產生短效期的 JWT 權杖並傳給嵌入內容。

|名詞|意義|
|---|---|
|**簽章密鑰**|每份表單各發行一個的值。主機伺服器用這個值為權杖簽章。|
|**權杖**|主機伺服器為每位訪客簽章產生的短效期 JWT。|

### 保管簽章密鑰

把複製下來的密鑰存放在主機伺服器的環境變數中。

```bash
WALLA_EMBED_SECRET=在此貼上複製的值
```

<Callout type="warning" title="注意事項">
請勿把簽章密鑰放進瀏覽器 bundle、前端程式碼或版控倉庫。一旦外洩，任何人都能偽造權杖。密鑰是每份表單各自不同的，若嵌入多份表單，就必須分別保管。
</Callout>

### 為權杖簽章

每當訪客開啟頁面時，都要在伺服器端重新簽章一個權杖。以下是使用 `jose` 的範例。

```js
import { SignJWT } from 'jose';

const secret = new TextEncoder().encode(process.env.WALLA_EMBED_SECRET);

const token = await new SignJWT({ email: user.email })
  .setProtectedHeader({ alg: 'HS256' })
  .setSubject(user.id)          // 會員識別模式必填
  .setAudience('{formId}')      // Walla 表單 ID
  .setExpirationTime('5m')
  .sign(secret);
```

在 `主機簽章權杖` 模式下不需要 `.setSubject(...)`。在 `主機簽章權杖 + 會員識別` 模式下，則必須把會員 ID 放進 `sub`。

### 權杖規則

|項目|要求|
|---|---|
|`alg`|只能使用 `HS256`。|
|簽章金鑰|使用簽章密鑰字串的 UTF-8 位元組。|
|`aud`|必須與表單 ID 相同。若為陣列，則必須包含表單 ID。|
|`exp`|必填，最多只能設到 10 分鐘後。建議效期為 5 分鐘。|
|`sub`|會員識別模式必填，且長度須在 255 字元以內。|
|`email`|選填。|
|編碼|使用 base64url 字元（`A-Za-z0-9_-`）。|

## 把權杖傳給 iframe

你可以在儀表板的 **分享 → 嵌入程式碼** 中複製基本的嵌入程式碼。

### 簽章模式

權杖要透過 URL fragment（`#`）傳遞。

```html
<iframe
  src="https://表單網址/f/{formId}#embedToken=已簽章的權杖"
  width="100%"
  height="500"
  style="border:0"
  loading="lazy">
</iframe>
```

<Callout type="warning" title="注意事項">
請不要用查詢字串（`?embedToken=`）傳送權杖。查詢字串可能會留在伺服器存取紀錄與 Referer 標頭中。請務必使用 fragment（`#embedToken=`）。
</Callout>

### 僅限允許的網站模式

這個模式不需要權杖。

```html
<iframe
  src="https://表單網址/f/{formId}"
  width="100%"
  height="500"
  style="border:0"
  loading="lazy">
</iframe>
```

允許的 origin 只填通訊協定與主機名稱，例如 `https://your-site.com`。請不要加上結尾斜線或路徑。

### 通過後的工作階段

通過閘道一次後，結果會保留 2 小時。在這段時間內，填答者不需要新權杖也能重新整理畫面。

## 串接流程

在簽章模式下，表單會依以下順序開啟。

1. 確認使用者是否已登入我方服務。
2. 用發行到的簽章密鑰為權杖簽章。若是會員識別模式，還要在權杖中一併帶入會員 ID。
3. 把簽章後的權杖放進 URL fragment 來開啟表單。
4. Walla 驗證權杖的簽章與 origin 後顯示表單。

## 疑難排解

<Accordions>
  <Accordion title="明明是允許的網站，表單卻打不開">
    **原因** 允許的 origin 中含有路徑或結尾斜線。**解決方式** 只留下通訊協定與主機名稱再儲存一次。
  </Accordion>

  <Accordion title="感覺限制沒有生效">
    **原因** 使用 `僅限允許的網站` 模式，但允許的 origin 是空的。**解決方式** 至少登錄一個 origin。
  </Accordion>

  <Accordion title="重新發行密鑰後突然全部被擋">
    **原因** 主機伺服器還在用舊密鑰簽章。**解決方式** 把主機的密鑰換成新值並重新部署。已開啟的工作階段最長會維持 2 小時，超過之後所有連線都會被擋。
  </Accordion>

  <Accordion title="有送權杖卻一直被拒絕">
    可能是權杖放在查詢字串中、已過期，或簽章與 `aud` 值不正確。請確認權杖是否以 fragment（`#embedToken=`）傳遞，並檢查主機伺服器的簽章密鑰、`aud` 與 `exp`。
  </Accordion>

  <Accordion title="會員 ID 沒有反映在重複回覆判定上">
    請確認模式是不是 `主機簽章權杖`。若要以會員為單位限制重複回覆，必須使用 `主機簽章權杖 + 會員識別` 模式，並把會員 ID 放進權杖的 `sub`。
  </Accordion>

  <Accordion title="重新發行後仍以舊的會員資訊送出回覆">
    可能還有已開啟的工作階段。通過閘道的工作階段最長會維持 2 小時。請在 2 小時後用新權杖再確認一次。
  </Accordion>
</Accordions>

## 上線前檢查清單

- [ ] 已確認想使用的模式在目前方案中有支援。
- [ ] 允許的 origin 只填了通訊協定與主機名稱。
- [ ] 簽章密鑰只保存在主機伺服器的環境變數中。
- [ ] 每次請求都重新產生權杖，且效期設為 5 分鐘。
- [ ] `aud` 填入了正確的表單 ID。
- [ ] 會員識別模式的權杖中有帶 `sub`。
- [ ] iframe 是以 fragment（`#embedToken=`）傳遞權杖。
- [ ] 已在實際嵌入頁面確認表單能正常開啟與送出。

<Callout title="這些情況適合使用">
- 把問卷嵌入公司內部入口或會員頁面，想避免連結外流時
- 只有我方服務的會員才能作答時
- 想讓每位會員只作答一次，但又覺得另外做電子郵件驗證太麻煩時
</Callout>

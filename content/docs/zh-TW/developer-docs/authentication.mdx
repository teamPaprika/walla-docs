# 驗證

Walla Open API 以 API 金鑰或 OAuth 存取權杖進行驗證。所有 API 請求都必須在標頭中帶上其中一種。OAuth 權杖只能用於部分讀取作業與回覆檔案下載。

## 選擇驗證方式

| 項目 | API 金鑰 | OAuth 存取權杖 |
|------|--------|-------------------|
| 標頭 | `X-WALLA-API-KEY: <API 金鑰>` | `Authorization: Bearer <存取權杖>` |
| 團隊範圍 | 金鑰所屬的團隊（不需指定團隊） | 權杖使用者所屬的團隊。`GET /workspaces`、`GET /forms` 需要 `teamId`（[指定團隊](#指定團隊)） |
| 可用作業 | 所有 Open API 作業 | 僅限讀取作業與回覆檔案下載（[範圍與可用作業](#範圍與可用作業)） |
| 權限 | 連結到 API 金鑰的權限 | 權杖使用者的團隊成員資格、工作區存取、回覆查詢與檔案下載權限 |
| 速率限制 | 每把 API 金鑰每小時 6,000 次 | 依方案、以團隊為單位的每小時配額（[OAuth 權杖呼叫配額](#oauth-權杖呼叫配額)） |
| 適用情境 | 團隊層級的伺服器整合，以及回覆搜尋、匯出、發送與寫入作業 | 在使用者權限範圍內讀取資料的應用程式 |

同時送出兩種標頭時，會優先套用 API 金鑰。既有的 API 金鑰整合會照常運作。

## API 金鑰驗證

請在所有請求的 `X-WALLA-API-KEY` 標頭中帶上 API 金鑰。

### 標頭格式

```
X-WALLA-API-KEY: your_api_key_here
```

### 團隊範圍的 API 金鑰

Walla API 金鑰是以**團隊為單位**建立的。

- 每把 API 金鑰都連結到特定團隊
- 團隊資訊會自動包含在所有請求中
- 呼叫 API 時不需要另外傳送團隊資訊
- 工作區、表單與回覆會自動以該團隊範圍篩選

## 取得 API 金鑰

1. 登入 [app.walla.my](https://app.walla.my)
2. 前往 [app.walla.my/open-api/doc](https://app.walla.my/open-api/doc)
3. 在頁面上方的 API 金鑰區塊建立或複製金鑰

> **重要**：請像保管密碼一樣妥善保存 API 金鑰，切勿對外分享。

## 發送已驗證的請求

各語言帶上 API 金鑰的方式如下。

### cURL

```bash
curl -X GET "https://api.walla.my/open-api/v1/workspaces" \
  -H "X-WALLA-API-KEY: your_api_key_here" \
  -H "Content-Type: application/json"
```

### JavaScript (Fetch)

```javascript
fetch('https://api.walla.my/open-api/v1/workspaces', {
  method: 'GET',
  headers: {
    'X-WALLA-API-KEY': 'your_api_key_here',
    'Content-Type': 'application/json'
  }
})
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('錯誤:', error));
```

### Python (requests)

```python
import requests

url = "https://api.walla.my/open-api/v1/workspaces"
headers = {
    "X-WALLA-API-KEY": "your_api_key_here",
    "Content-Type": "application/json"
}

response = requests.get(url, headers=headers)
data = response.json()
print(data)
```

### Node.js (axios)

```javascript
const axios = require('axios');

const config = {
  headers: {
    'X-WALLA-API-KEY': 'your_api_key_here',
    'Content-Type': 'application/json'
  }
};

axios.get('https://api.walla.my/open-api/v1/workspaces', config)
  .then(response => console.log(response.data))
  .catch(error => console.error('錯誤:', error));
```

## OAuth 存取權杖

OAuth 存取權杖透過 `Authorization: Bearer <存取權杖>` 標頭送出。路徑與回應格式和 API 金鑰呼叫相同，但只能呼叫下表列出的作業。

### 取得權杖

權杖透過 OAuth authorization code 流程取得。請求時請遵守下列事項。

- 務必一併請求 `openid` 範圍（scope）。若缺少，所有呼叫都會回傳 `401`，更新權杖也無法解決。
- 請依要使用的作業請求對應的範圍（`project:read`、`project:response.read`、`project:response.download`）。
- 若要更新權杖，也請請求 `offline_access`。缺少時不會發行 refresh 權杖。
- 請勿送出 `resource` 參數（RFC 8707）。送出後，用該權杖進行的所有呼叫都會回傳 `403 insufficient_scope`。

部分部署環境（例如地端部署）可能已停止發行與更新新權杖。即使如此，已發行的權杖在過期或被撤銷前仍可繼續使用。

### 範圍與可用作業

路徑以 `/open-api/v1` 為基準。

| 範圍 | 可用作業 |
|--------|------------------|
| `project:read` | `GET /teams`<br />`GET /workspaces`, `GET /workspaces/{workspaceId}`, `GET /workspaces/{workspaceId}/forms`<br />`GET /forms`, `GET /forms/{formId}`<br />`GET /forms/{formId}/fields`, `GET /forms/{formId}/fields/{fieldId}`, `GET /forms/{formId}/fields/{fieldId}/description`<br />`GET /forms/{formId}/hidden-fields`<br />`POST /forms/{formId}/exports/field-definitions`<br />`GET /field-output-schemas` |
| `project:response.read` | `GET /forms/{formId}/responses` |
| `project:response.download` | `POST /forms/{formId}/responses/{responseId}/fields/{fieldId}/file`（[下載回覆檔案（英文）](/en/docs/developer-docs/responses#download-a-response-file)） |

**僅限 API 金鑰的作業**：以 OAuth 權杖呼叫下列作業時，會回傳 `403 This endpoint does not accept OAuth tokens`。

- 查詢特定回覆 `GET /forms/{formId}/responses/{responseId}`
- 搜尋回覆 `POST /forms/{formId}/responses/search`
- 匯出回覆 `POST /forms/{formId}/exports/responses`
- 發送表單（`/forms/{formId}/delivery` 底下的所有作業）
- 新增 `POST`／刪除 `DELETE` 隱藏欄位

### 指定團隊

以 OAuth 權杖呼叫 `GET /workspaces` 或 `GET /forms` 時，需要 `teamId` 查詢參數。缺少時會回傳 `400`。API 金鑰呼叫會忽略 `teamId`。

團隊 ID 請用 [`GET /teams`（英文）](/en/docs/developer-docs/workspaces#list-teams)確認。以權杖呼叫時，只會回傳權杖使用者所屬團隊中，通過 Open API 啟用設定與 IP 存取限制的團隊。

```json
{
  "success": true,
  "data": [
    { "id": "team_456", "name": "行銷團隊", "profileUrl": null }
  ]
}
```

- 未啟用兩步驟驗證的訪客也會在清單中看到團隊，但該團隊的作業會回傳 `403`。
- 以權杖呼叫 `GET /workspaces/{workspaceId}` 時，若權杖使用者無法存取該工作區，會回傳 `403 {"error":"Access denied"}`。

### cURL 範例

以下範例假設你已把取得的存取權杖存放在 `WALLA_OAUTH_TOKEN` 環境變數中。

```bash
# 1. 查詢可呼叫的團隊 (project:read)
curl -X GET "https://api.walla.my/open-api/v1/teams" \
  -H "Authorization: Bearer $WALLA_OAUTH_TOKEN"

# 2. 查詢團隊的工作區 (project:read，teamId 必填)
curl -X GET "https://api.walla.my/open-api/v1/workspaces?teamId=team_456" \
  -H "Authorization: Bearer $WALLA_OAUTH_TOKEN"

# 3. 查詢表單回覆清單 (project:response.read)
curl -X GET "https://api.walla.my/open-api/v1/forms/form_abc/responses" \
  -H "Authorization: Bearer $WALLA_OAUTH_TOKEN"
```

回覆檔案下載範例請參閱[下載回覆檔案（英文）](/en/docs/developer-docs/responses#download-a-response-file)。

## 驗證錯誤

驗證失敗時會回傳下列錯誤。

### 401 Unauthorized

在下列情況下發生。
- 請求中缺少 API 金鑰
- API 金鑰無效，或已過期／被撤銷

**回應範例：**

```json
{
  "error": "Unauthorized"
}
```

### 403 Forbidden

在通過驗證但沒有存取該資源的權限時發生。

**回應範例：**

```json
{
  "error": "Forbidden"
}
```

### OAuth 權杖錯誤

- **401**：權杖無效或已過期。回應會包含 `WWW-Authenticate: Bearer error="invalid_token"` 標頭。只有這種情況需要更新權杖。
- **403 `insufficient_scope`**：權杖缺少所需的範圍。本文為 `{"error":"insufficient_scope","scope":"<所需範圍>"}`。
- **403 `This endpoint does not accept OAuth tokens`**：這是[僅限 API 金鑰的作業](#範圍與可用作業)。請改用 API 金鑰呼叫。
- **403 `Forbidden`**：不是團隊成員、是未啟用兩步驟驗證的訪客，或是無法存取的工作區 ID。
- **403 `Unauthorized`**：伺服器無法驗證權杖。這不代表權杖無效，請勿更新權杖，稍後再試。

完整的錯誤清單請參閱[錯誤代碼](/zh-TW/docs/developer-docs/error-codes)。

## 最佳做法

### 安全性

- **不要把 API 金鑰提交進版控** - 請勿把 API 金鑰放進 Git 等版本控制系統
- **使用環境變數** - 請以環境變數管理 API 金鑰
- **定期更換金鑰** - 為了安全請定期更新金鑰
- **依環境分開金鑰** - 開發、測試、正式環境請各自使用不同的金鑰

### 環境變數

請把 API 金鑰存放在環境變數中。

```bash
# .env 檔案
WALLA_API_KEY=your_api_key_here
```

在程式碼中可以像下面這樣讀取。

```javascript
// JavaScript
const apiKey = process.env.WALLA_API_KEY;
```

```python
# Python
import os
api_key = os.getenv('WALLA_API_KEY')
```

### 速率限制

Walla Open API 為了系統穩定性設有速率限制。

- **限制**：每把 API 金鑰每小時 6,000 次
- **時間視窗**：1 小時（滾動視窗）

超過速率限制時會回傳 `429 Too Many Requests`。此時請：

- 以指數退避（exponential backoff）方式重試
- 盡可能快取回應
- 減少不必要的重複請求
- 監控 API 使用量
- 盡可能把請求批次處理

上述限制適用於 API 金鑰呼叫。

#### OAuth 權杖呼叫配額

OAuth 權杖呼叫與 API 金鑰每小時 6,000 次的限制分開計算，所有方案都可以使用。方案只決定配額。一個團隊的配額由該團隊所有使用者與應用程式共用。

| 對象 | 每小時配額 |
|------|---------------|
| Free 方案團隊 | 600 次 |
| Pro 方案團隊 | 3,000 次 |
| Enterprise／自訂方案團隊 | 6,000 次 |
| `GET /teams`, `GET /field-output-schemas` | 每位使用者 600 次 |

- 1 小時的視窗從該團隊（或使用者）的第一次呼叫開始計算。
- 超過配額時會回傳 `429 {"error":"rate_limit_exceeded"}`，並包含 `Retry-After`（秒）、`RateLimit-Limit`、`RateLimit-Remaining`、`RateLimit-Reset` 標頭。請等待 `Retry-After` 指定的時間後再重試。
- 超過配額後送出的呼叫也會計入次數。
- 團隊的 Open API 啟用設定與 IP 存取限制與方案無關，一律適用。

## 疑難排解

### 常見問題

**問題**：已帶上 API 金鑰卻仍出現 401 錯誤

**解決方式**：
- 確認 API 金鑰正確且尚未過期
- 確認你對該工作區具有權限
- 確認標頭名稱正好是 `X-WALLA-API-KEY`（區分大小寫）
- 確認該資源屬於你有存取權限的工作區

**問題**：API 金鑰沒有被送出

**解決方式**：
- 確認標頭格式正確
- 確認 HTTP 用戶端有帶上自訂標頭
- 確認標頭名稱沒有拼字錯誤

**問題**：以 OAuth 權杖呼叫 `GET /workspaces` 或 `GET /forms` 時出現 400 錯誤

**解決方式**：
- 請帶上 `teamId` 查詢參數。團隊 ID 可以用 `GET /teams` 確認

**問題**：OAuth 權杖呼叫回傳 403 錯誤

**解決方式**：
- 若是 `insufficient_scope`，請確認已請求所需的範圍，且權杖請求中沒有送出 `resource` 參數
- 若是 `This endpoint does not accept OAuth tokens`，請改用 API 金鑰呼叫
- 若是 `Unauthorized`，請勿更新權杖，稍後再試

## 其他安全性考量

### 保護 API 金鑰

1. **不要寫死在程式碼中**
   - 請勿把 API 金鑰直接放進原始碼
   - 請使用環境變數或密鑰管理服務

2. **只使用 HTTPS**
   - API 只能透過 HTTPS 存取
   - HTTP 請求會被拒絕

3. **監控金鑰外洩**
   - 定期確認金鑰沒有被推送到公開的儲存庫
   - 一旦金鑰外洩，請立即撤銷並重新發行

### 權限管理

- API 金鑰會連結到工作區權限
- 請為每位團隊成員各自發行 API 金鑰
- 不再使用的金鑰請立即撤銷
- 請定期檢視 API 金鑰的使用狀況
- OAuth 權杖呼叫會套用權杖使用者的團隊成員資格、工作區存取權限，以及回覆查詢與檔案下載權限

### 錯誤處理最佳做法

```javascript
async function makeAuthenticatedRequest(url) {
  try {
    const response = await fetch(url, {
      headers: {
        'X-WALLA-API-KEY': process.env.WALLA_API_KEY,
        'Content-Type': 'application/json'
      }
    });

    if (response.status === 401) {
      console.error('驗證失敗：請確認 API 金鑰');
      // 通知使用者或啟動重新驗證流程
      return null;
    }

    if (!response.ok) {
      throw new Error(`HTTP 錯誤！狀態: ${response.status}`);
    }

    return await response.json();
  } catch (error) {
    console.error('請求失敗:', error);
    throw error;
  }
}
```

```python
import requests
import os

def make_authenticated_request(url):
    headers = {
        'X-WALLA-API-KEY': os.getenv('WALLA_API_KEY'),
        'Content-Type': 'application/json'
    }

    try:
        response = requests.get(url, headers=headers)

        if response.status_code == 401:
            print('驗證失敗：請確認 API 金鑰')
            return None

        response.raise_for_status()
        return response.json()

    except requests.RequestException as e:
        print(f'請求失敗: {e}')
        raise
```

# Autenticación

La Walla Open API se autentica con una clave de API o con un token de acceso OAuth. Todas las peticiones deben incluir una de las dos credenciales en la cabecera. Los tokens OAuth solo sirven para algunas operaciones de lectura y para descargar archivos de respuestas.

## Elegir el método de autenticación

| Aspecto | Clave de API | Token de acceso OAuth |
|------|--------|-------------------|
| Cabecera | `X-WALLA-API-KEY: <clave de API>` | `Authorization: Bearer <token de acceso>` |
| Alcance de equipo | El equipo para el que se generó la clave (no hace falta indicar el equipo) | Los equipos a los que pertenece el usuario del token. `GET /workspaces` y `GET /forms` requieren `teamId` ([Indicar el equipo](#indicar-el-equipo)) |
| Operaciones disponibles | Todas las operaciones de la Open API | Solo operaciones de lectura y descarga de archivos de respuestas ([Scopes y operaciones permitidas](#scopes-y-operaciones-permitidas)) |
| Permisos | Los permisos vinculados a la clave de API | La pertenencia al equipo, el acceso a espacios de trabajo y los permisos para ver respuestas y descargar archivos del usuario del token |
| Límite de peticiones | 6.000 peticiones por hora y clave de API | Cuota por hora y por equipo según el plan ([Cuota de llamadas con tokens OAuth](#cuota-de-llamadas-con-tokens-oauth)) |
| Cuándo usarlo | Integraciones de servidor a nivel de equipo y operaciones de búsqueda, exportación, envío y escritura de respuestas | Aplicaciones que leen datos dentro de los permisos del usuario |

Si envías ambas cabeceras, se aplica la clave de API. Las integraciones existentes con clave de API siguen funcionando igual.

## Autenticación con clave de API

Incluye la clave de API en la cabecera `X-WALLA-API-KEY` de todas las peticiones.

### Formato de la cabecera

```
X-WALLA-API-KEY: your_api_key_here
```

### Claves de API con alcance de equipo

Las claves de API de Walla se generan **por equipo**.

- Cada clave está vinculada a un equipo concreto
- La información del equipo se incluye automáticamente en todas las peticiones
- No hace falta enviar los datos del equipo por separado al llamar a la API
- Los espacios de trabajo, formularios y respuestas se filtran automáticamente al alcance de ese equipo

## Obtener una clave de API

1. Inicia sesión en [app.walla.my](https://app.walla.my)
2. Ve a [app.walla.my/open-api/doc](https://app.walla.my/open-api/doc)
3. Genera o copia la clave en la sección de claves de API de la parte superior de la página

> **Importante**: guarda la clave de API con el mismo cuidado que una contraseña y no la compartas con nadie.

## Enviar peticiones autenticadas

Así se incluye la clave de API en cada lenguaje.

### cURL

```bash
curl -X GET "https://api.walla.my/open-api/v1/workspaces" \
  -H "X-WALLA-API-KEY: your_api_key_here" \
  -H "Content-Type: application/json"
```

### JavaScript (Fetch)

```javascript
fetch('https://api.walla.my/open-api/v1/workspaces', {
  method: 'GET',
  headers: {
    'X-WALLA-API-KEY': 'your_api_key_here',
    'Content-Type': 'application/json'
  }
})
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('Error:', error));
```

### Python (requests)

```python
import requests

url = "https://api.walla.my/open-api/v1/workspaces"
headers = {
    "X-WALLA-API-KEY": "your_api_key_here",
    "Content-Type": "application/json"
}

response = requests.get(url, headers=headers)
data = response.json()
print(data)
```

### Node.js (axios)

```javascript
const axios = require('axios');

const config = {
  headers: {
    'X-WALLA-API-KEY': 'your_api_key_here',
    'Content-Type': 'application/json'
  }
};

axios.get('https://api.walla.my/open-api/v1/workspaces', config)
  .then(response => console.log(response.data))
  .catch(error => console.error('Error:', error));
```

## Tokens de acceso OAuth

El token de acceso OAuth se envía en la cabecera `Authorization: Bearer <token de acceso>`. Las rutas y el formato de las respuestas son los mismos que con clave de API, pero solo se pueden llamar las operaciones de la tabla siguiente.

### Obtener un token

Los tokens se obtienen con el flujo OAuth authorization code. Al solicitarlo, ten en cuenta lo siguiente.

- Solicita siempre el scope `openid`. Si falta, todas las llamadas devuelven `401` y renovar el token no lo soluciona.
- Solicita los scopes que correspondan a las operaciones que vas a usar (`project:read`, `project:response.read`, `project:response.download`).
- Para poder renovar el token, solicita también `offline_access`. Sin él no se emite un refresh token.
- No envíes el parámetro `resource` (RFC 8707). Si lo envías, todas las llamadas con ese token devuelven `403 insufficient_scope`.

En algunos entornos de despliegue (por ejemplo, instalaciones on-premises) puede estar desactivada la emisión y renovación de tokens nuevos. Aun así, los tokens ya emitidos se pueden seguir usando hasta que caduquen o se revoquen.

### Scopes y operaciones permitidas

Las rutas son relativas a `/open-api/v1`.

| Scope | Operaciones permitidas |
|--------|------------------|
| `project:read` | `GET /teams`<br />`GET /workspaces`, `GET /workspaces/{workspaceId}`, `GET /workspaces/{workspaceId}/forms`<br />`GET /forms`, `GET /forms/{formId}`<br />`GET /forms/{formId}/fields`, `GET /forms/{formId}/fields/{fieldId}`, `GET /forms/{formId}/fields/{fieldId}/description`<br />`GET /forms/{formId}/hidden-fields`<br />`POST /forms/{formId}/exports/field-definitions`<br />`GET /field-output-schemas` |
| `project:response.read` | `GET /forms/{formId}/responses` |
| `project:response.download` | `POST /forms/{formId}/responses/{responseId}/fields/{fieldId}/file` ([Descargar un archivo de respuesta, en inglés](/en/docs/developer-docs/responses#download-a-response-file)) |

**Operaciones solo con clave de API**: si llamas a estas operaciones con un token OAuth, se devuelve `403 This endpoint does not accept OAuth tokens`.

- Consultar una respuesta concreta `GET /forms/{formId}/responses/{responseId}`
- Buscar respuestas `POST /forms/{formId}/responses/search`
- Exportar respuestas `POST /forms/{formId}/exports/responses`
- Envío de formularios (todas las operaciones bajo `/forms/{formId}/delivery`)
- Añadir `POST` y eliminar `DELETE` campos ocultos

### Indicar el equipo

Al llamar a `GET /workspaces` o `GET /forms` con un token OAuth, el parámetro de consulta `teamId` es obligatorio. Si falta, se devuelve `400`. En las llamadas con clave de API, `teamId` se ignora.

Consulta los ID de equipo con [`GET /teams` (en inglés)](/en/docs/developer-docs/workspaces#list-teams). Con un token, solo se devuelven los equipos del usuario del token que superan la configuración de uso de la Open API y la restricción de acceso por IP.

```json
{
  "success": true,
  "data": [
    { "id": "team_456", "name": "Equipo de marketing", "profileUrl": null }
  ]
}
```

- A los invitados sin verificación en dos pasos también se les muestra el equipo en la lista, pero las operaciones de ese equipo devuelven `403`.
- Si llamas a `GET /workspaces/{workspaceId}` con un token y el usuario del token no tiene acceso a ese espacio de trabajo, se devuelve `403 {"error":"Access denied"}`.

### Ejemplos de cURL

Estos ejemplos suponen que ya guardaste un token de acceso emitido en la variable de entorno `WALLA_OAUTH_TOKEN`.

```bash
# 1. Consultar los equipos disponibles (project:read)
curl -X GET "https://api.walla.my/open-api/v1/teams" \
  -H "Authorization: Bearer $WALLA_OAUTH_TOKEN"

# 2. Consultar los espacios de trabajo del equipo (project:read, teamId obligatorio)
curl -X GET "https://api.walla.my/open-api/v1/workspaces?teamId=team_456" \
  -H "Authorization: Bearer $WALLA_OAUTH_TOKEN"

# 3. Consultar las respuestas de un formulario (project:response.read)
curl -X GET "https://api.walla.my/open-api/v1/forms/form_abc/responses" \
  -H "Authorization: Bearer $WALLA_OAUTH_TOKEN"
```

Para ver un ejemplo de descarga de archivos de respuestas, consulta [Descargar un archivo de respuesta (en inglés)](/en/docs/developer-docs/responses#download-a-response-file).

## Errores de autenticación

Cuando falla la autenticación se devuelven los siguientes errores.

### 401 Unauthorized

Se produce en estos casos.
- La petición no incluye la clave de API
- La clave no es válida, ha caducado o se ha revocado

**Ejemplo de respuesta:**

```json
{
  "error": "Unauthorized"
}
```

### 403 Forbidden

Se produce cuando la autenticación es correcta pero no tienes permiso para acceder a ese recurso.

**Ejemplo de respuesta:**

```json
{
  "error": "Forbidden"
}
```

### Errores de tokens OAuth

- **401**: el token no es válido o ha caducado. La respuesta incluye la cabecera `WWW-Authenticate: Bearer error="invalid_token"`. Es el único caso en el que debes renovar el token.
- **403 `insufficient_scope`**: al token le falta el scope necesario. El cuerpo es `{"error":"insufficient_scope","scope":"<scope necesario>"}`.
- **403 `This endpoint does not accept OAuth tokens`**: es una [operación solo con clave de API](#scopes-y-operaciones-permitidas). Llámala con una clave de API.
- **403 `Forbidden`**: no eres miembro del equipo, eres un invitado sin verificación en dos pasos o el ID corresponde a un espacio de trabajo al que no tienes acceso.
- **403 `Unauthorized`**: el servidor no pudo verificar el token. No significa que el token no sea válido, así que no lo renueves y vuelve a intentarlo más tarde.

Consulta la lista completa de errores en [Códigos de error](/es/docs/developer-docs/error-codes).

## Buenas prácticas

### Seguridad

- **No subas la clave al repositorio**: no incluyas claves de API en Git ni en otros sistemas de control de versiones
- **Usa variables de entorno**: gestiona la clave mediante variables de entorno
- **Rota las claves con regularidad**: renuévalas periódicamente por seguridad
- **Separa las claves por entorno**: usa claves distintas en desarrollo, preproducción y producción

### Variables de entorno

Guarda la clave de API en una variable de entorno.

```bash
# Archivo .env
WALLA_API_KEY=your_api_key_here
```

En el código puedes leerla así.

```javascript
// JavaScript
const apiKey = process.env.WALLA_API_KEY;
```

```python
# Python
import os
api_key = os.getenv('WALLA_API_KEY')
```

### Límite de peticiones

La Walla Open API aplica límites de peticiones para garantizar la estabilidad del sistema.

- **Límite**: 6.000 peticiones por hora y clave de API
- **Ventana temporal**: 1 hora (ventana deslizante)

Si superas el límite se devuelve `429 Too Many Requests`. En ese caso:

- Reintenta con retroceso exponencial
- Cachea las respuestas siempre que puedas
- Reduce las peticiones duplicadas innecesarias
- Monitoriza tu consumo de la API
- Agrupa las peticiones cuando sea posible

Estos límites se aplican a las llamadas con clave de API.

#### Cuota de llamadas con tokens OAuth

Las llamadas con tokens OAuth se cuentan aparte del límite de 6.000 peticiones por hora de la clave de API y están disponibles en todos los planes. El plan solo determina la cuota. Todos los usuarios y aplicaciones de un equipo comparten la cuota de ese equipo.

| Ámbito | Cuota por hora |
|------|---------------|
| Equipos del plan Free | 600 llamadas |
| Equipos del plan Pro | 3.000 llamadas |
| Equipos de planes Enterprise y personalizados | 6.000 llamadas |
| `GET /teams`, `GET /field-output-schemas` | 600 llamadas por usuario |

- La ventana de 1 hora empieza con la primera llamada del equipo (o del usuario).
- Si superas la cuota, se devuelve `429 {"error":"rate_limit_exceeded"}` con las cabeceras `Retry-After` (en segundos), `RateLimit-Limit`, `RateLimit-Remaining` y `RateLimit-Reset`. Espera el tiempo indicado en `Retry-After` antes de reintentar.
- Las llamadas enviadas después de superar la cuota también cuentan.
- La configuración de uso de la Open API del equipo y la restricción de acceso por IP se aplican con independencia del plan.

## Resolución de problemas

### Problemas habituales

**Problema**: incluyo la clave de API pero sigue saliendo un error 401

**Solución**:
- Comprueba que la clave sea correcta y no haya caducado
- Comprueba que tengas permisos sobre ese espacio de trabajo
- Comprueba que el nombre de la cabecera sea exactamente `X-WALLA-API-KEY` (distingue mayúsculas y minúsculas)
- Comprueba que el recurso pertenezca a un espacio al que tengas acceso

**Problema**: la clave de API no se está enviando

**Solución**:
- Comprueba que el formato de la cabecera sea correcto
- Comprueba que tu cliente HTTP incluya las cabeceras personalizadas
- Comprueba que no haya erratas en el nombre de la cabecera

**Problema**: al llamar a `GET /workspaces` o `GET /forms` con un token OAuth se produce un error 400

**Solución**:
- Incluye el parámetro de consulta `teamId`. Puedes consultar los ID de equipo con `GET /teams`

**Problema**: las llamadas con token OAuth devuelven un error 403

**Solución**:
- Si es `insufficient_scope`, comprueba que solicitaste el scope necesario y que no enviaste el parámetro `resource` al pedir el token
- Si es `This endpoint does not accept OAuth tokens`, llama con una clave de API
- Si es `Unauthorized`, no renueves el token y vuelve a intentarlo más tarde

## Otras consideraciones de seguridad

### Proteger la clave de API

1. **No la escribas directamente en el código**
   - No pongas la clave de API en el código fuente
   - Usa variables de entorno o un servicio de gestión de secretos

2. **Usa solo HTTPS**
   - A la API solo se puede acceder por HTTPS
   - Las peticiones HTTP se rechazan

3. **Vigila posibles filtraciones**
   - Comprueba con regularidad que la clave no haya acabado en un repositorio público
   - Si se filtra, revócala de inmediato y genera una nueva

### Gestión de permisos

- Las claves de API están vinculadas a los permisos del espacio de trabajo
- Genera una clave distinta para cada miembro del equipo
- Revoca cuanto antes las claves que ya no uses
- Revisa periódicamente el uso de las claves
- A las llamadas con token OAuth se les aplican la pertenencia al equipo, el acceso a espacios de trabajo y los permisos para ver respuestas y descargar archivos del usuario del token

### Buenas prácticas para gestionar errores

```javascript
async function makeAuthenticatedRequest(url) {
  try {
    const response = await fetch(url, {
      headers: {
        'X-WALLA-API-KEY': process.env.WALLA_API_KEY,
        'Content-Type': 'application/json'
      }
    });

    if (response.status === 401) {
      console.error('Fallo de autenticación: revisa la clave de API');
      // Avisa a la persona usuaria o inicia el proceso de reautenticación
      return null;
    }

    if (!response.ok) {
      throw new Error(`Error HTTP. Estado: ${response.status}`);
    }

    return await response.json();
  } catch (error) {
    console.error('Petición fallida:', error);
    throw error;
  }
}
```

```python
import requests
import os

def make_authenticated_request(url):
    headers = {
        'X-WALLA-API-KEY': os.getenv('WALLA_API_KEY'),
        'Content-Type': 'application/json'
    }

    try:
        response = requests.get(url, headers=headers)

        if response.status_code == 401:
            print('Fallo de autenticación: revisa la clave de API')
            return None

        response.raise_for_status()
        return response.json()

    except requests.RequestException as e:
        print(f'Petición fallida: {e}')
        raise
```

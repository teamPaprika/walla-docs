# Error Codes

This guide provides detailed information about error responses you may encounter when using the Walla Open API.

## HTTP Status Codes

The Walla API uses standard HTTP status codes to indicate the success or failure of requests.

### Success Codes

| Code | Status | Description |
|------|--------|-------------|
| 200 | OK | Request succeeded |

### Error Codes

| Code | Status | Description |
|------|--------|-------------|
| 400 | Bad Request | Invalid request parameters or malformed request |
| 401 | Unauthorized | Authentication failed (API key or OAuth token missing, invalid or expired) |
| 403 | Forbidden | Insufficient permissions for the requested resource |
| 404 | Not Found | Resource not found |
| 413 | Payload Too Large | Request body over 4KiB or file over 500MiB (response file download) |
| 429 | Too Many Requests | Rate limit exceeded |
| 500 | Internal Server Error | Server error occurred |
| 502 | Bad Gateway | The file could not be fetched from storage (response file download) |

## Error Response Format

All error responses follow a consistent JSON format:

```json
{
  "error": "Error message describing what went wrong"
}
```

Some errors include additional fields such as `code`, `detailsType`/`details` or `scope`.

## Detailed Error Codes

### 400 Bad Request

Indicates that the request was malformed or contains invalid parameters.

**Common Causes:**

1. **Missing Required Fields**
   ```json
   {
     "error": "Invalid request: recipients array is required"
   }
   ```
   **Solution**: Include all required fields in your request body.

2. **Invalid Data Format**
   ```json
   {
     "error": "Invalid email format"
   }
   ```
   **Solution**: Ensure email addresses follow the format `user@domain.com`.

3. **Empty Arrays**
   ```json
   {
     "error": "Recipients array must contain at least one recipient"
   }
   ```
   **Solution**: Provide at least one item in required arrays.

4. **Invalid Pagination Parameters**
   ```json
   {
     "error": "Invalid page number. Page must be >= 1"
   }
   ```
   **Solution**: Use page numbers starting from 1, not 0.

5. **Limit Exceeded**
   ```json
   {
     "error": "Limit cannot exceed 100"
   }
   ```
   **Solution**: Keep the `limit` parameter at or below 100.

6. **Missing `teamId` in an OAuth Token Call**

   **Solution**: Include the `teamId` query parameter when calling `GET /workspaces` or `GET /forms` with a token. Look up team IDs with `GET /teams`.

7. **Missing Download Reason for a Secure File**
   ```json
   {
     "error": "A download reason is required for a secure file.",
     "code": "REASON_REQUIRED"
   }
   ```
   **Solution**: Include `reason` (1–500 characters) in the request body of [Download a response file](/en/docs/developer-docs/responses#download-a-response-file).

**Example Scenarios:**

```javascript
// ❌ Bad - Missing required field
await fetch(`${API_BASE}/forms/form_abc/delivery`, {
  method: 'POST',
  headers: headers,
  body: JSON.stringify({
    // Missing 'recipients' field
    subject: 'Survey'
  })
});
// Returns 400: recipients array is required

// ✅ Good
await fetch(`${API_BASE}/forms/form_abc/delivery`, {
  method: 'POST',
  headers: headers,
  body: JSON.stringify({
    recipients: [
      { customerKey: 'customer_001', email: 'user@example.com' }
    ],
    subject: 'Survey'
  })
});
```

### 401 Unauthorized

Authentication failed because the API key is missing or invalid. The response also carries a `WWW-Authenticate: ApiKey realm="walla-open-api"` header.

**Common Causes:**

1. **Missing API Key**
   ```json
   {
     "error": "Unauthorized"
   }
   ```
   **Solution**: Include the `X-WALLA-API-KEY` header in your request.

2. **Invalid or Expired API Key**
   ```json
   {
     "error": "Unauthorized"
   }
   ```
   **Solution**: Verify your API key is correct and hasn't expired or been revoked.

**For OAuth tokens**: If a token is invalid or expired, the API returns 401 with a `WWW-Authenticate: Bearer error="invalid_token"` header. Refresh the token in this case. If the `openid` scope was missing from the token request, refreshing still returns 401, so request a new token that includes `openid`.

**Example Scenarios:**

```javascript
// ❌ Bad - Missing API key
await fetch(`${API_BASE}/workspaces`, {
  method: 'GET',
  headers: {
    'Content-Type': 'application/json'
    // Missing X-WALLA-API-KEY
  }
});
// Returns 401

// ✅ Good
await fetch(`${API_BASE}/workspaces`, {
  method: 'GET',
  headers: {
    'X-WALLA-API-KEY': process.env.WALLA_API_KEY,
    'Content-Type': 'application/json'
  }
});
```

### 403 Forbidden

Authentication succeeded, but you don't have permission to access the requested resource.

**Common Causes:**

1. **Workspace or Form Access Denied**
   ```json
   {
     "error": "Forbidden"
   }
   ```
   **Solution**: Make sure the workspace or form belongs to your team, and contact your workspace administrator to grant access if needed.

2. **Insufficient OAuth Token Scope**
   ```json
   {
     "error": "insufficient_scope",
     "scope": "project:response.read"
   }
   ```
   **Solution**: Request a new token that includes the scope shown in `scope`. Also make sure you did not send the `resource` parameter in the token request.

3. **`This endpoint does not accept OAuth tokens`**

   **Solution**: This is an API key-only operation. Call it with an API key ([Scopes and allowed operations](/en/docs/developer-docs/authentication#scopes-and-allowed-operations)).

4. **`Unauthorized` (status 403, OAuth token)**

   **Solution**: The server could not verify the token. Do not refresh the token; try again shortly.

5. **`Open API is disabled for this team` / `Access from this IP address is not allowed`**

   **Solution**: Ask your team administrator to check the team's Open API setting and IP access restrictions.

6. **`Access denied`**

   **Solution**: Check the OAuth token user's workspace access, or, for file downloads, their response viewing and file download permissions.

7. **Response File Downloads**
   - `Approval required` (`code: "APPROVAL_REQUIRED"`, `actionKey`, `projectId`): Under the team's download approval policy, approval is required for the form identified by `projectId`.
   - `This field is masked and cannot be downloaded.`: Masked file fields cannot be downloaded through the Open API.
   - `Secure file access requires an enterprise plan.`: Secure file fields require a team plan that supports secure files.

**Troubleshooting Steps:**

1. Verify the API key is correctly set in your environment
2. Check the header name is exactly `X-WALLA-API-KEY` (case-sensitive)
3. Ensure the API key hasn't been revoked or expired
4. Confirm you have access to the requested workspace
5. Verify you're using the correct API key for your environment (dev/staging/production)

### 404 Not Found

Indicates that the requested resource doesn't exist or cannot be accessed.

**Common Causes:**

1. **Form Not Found**
   ```json
   {
     "error": "Form not found"
   }
   ```
   **Solution**: Verify the form ID exists and you have access to it.

2. **Unpublished Form**
   ```json
   {
     "error": "Form not found or not published"
   }
   ```
   **Solution**: Ensure the form is published before attempting to send deliveries.

3. **Response Not Found**
   ```json
   {
     "error": "Form or response not found"
   }
   ```
   **Solution**: Verify both the form ID and response ID are correct.

4. **Workspace Not Found**
   ```json
   {
     "error": "Workspace not found"
   }
   ```
   **Solution**: Check the workspace ID and ensure you have access.

**Example Scenarios:**

```javascript
// ❌ Bad - Trying to send unpublished form
await sendForm('unpublished_form_id', recipients);
// Returns 404: Form not found or not published

// ✅ Good - Form is published
await sendForm('published_form_id', recipients);
```

**Troubleshooting Steps:**

1. Verify the resource ID (form, response, workspace) is correct
2. Check if the form is published (for delivery operations)
3. Ensure the resource hasn't been deleted
4. Confirm you're using the correct environment (dev/production)

### 429 Too Many Requests

Indicates that you have exceeded the API rate limit.

**Rate Limits:**
- **Limit**: 6000 requests per hour per API key
- **Time Window**: 1 hour (rolling window)

**Response:**
```json
{
  "error": "Rate limit exceeded"
}
```

**OAuth token call quota**: OAuth token calls are subject to a per-team, plan-based quota that is separate from the API key limit above ([OAuth token call quota](/en/docs/developer-docs/authentication#oauth-token-call-quota)). When it is exceeded, the API returns the body below with the `Retry-After` (seconds), `RateLimit-Limit`, `RateLimit-Remaining` and `RateLimit-Reset` headers. Wait for `Retry-After` before retrying.

```json
{
  "error": "rate_limit_exceeded"
}
```

**What to Do:**

1. **Implement Rate Limit Handling**: Check response status and handle 429 appropriately
2. **Use Exponential Backoff**: Wait before retrying with increasing delays
3. **Cache Responses**: Store frequently accessed data to reduce API calls
4. **Batch Operations**: Combine multiple operations when possible
5. **Monitor Usage**: Track your API consumption to stay within limits

**Rate Limit Handling Example:**

```javascript
async function makeRequestWithRateLimit(url, options, maxRetries = 3) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      const response = await fetch(url, options);

      // Handle rate limit
      if (response.status === 429) {
        const retryAfter = response.headers.get('Retry-After') || Math.pow(2, i);
        console.log(`Rate limit exceeded. Retrying after ${retryAfter}s...`);
        await new Promise(resolve => setTimeout(resolve, retryAfter * 1000));
        continue;
      }

      if (!response.ok) {
        throw new Error(`HTTP ${response.status}`);
      }

      return await response.json();
    } catch (error) {
      if (i === maxRetries - 1) throw error;
    }
  }
}
```

```python
import time
import requests

def make_request_with_rate_limit(url, headers, max_retries=3):
    for i in range(max_retries):
        try:
            response = requests.get(url, headers=headers)

            # Handle rate limit
            if response.status_code == 429:
                retry_after = int(response.headers.get('Retry-After', 2 ** i))
                print(f'Rate limit exceeded. Retrying after {retry_after}s...')
                time.sleep(retry_after)
                continue

            response.raise_for_status()
            return response.json()

        except requests.RequestException as e:
            if i == max_retries - 1:
                raise
```

**Best Practices:**

- **Respect Rate Limits**: Design your application to stay within the 6000 requests/hour limit
- **Implement Caching**: Cache API responses for data that doesn't change frequently
- **Use Webhooks**: For real-time updates, consider using webhooks instead of polling
- **Batch Requests**: Retrieve multiple items in a single request when supported
- **Monitor and Alert**: Set up monitoring to track API usage and alert before hitting limits

### 413 Payload Too Large

Returned when [Download a response file](/en/docs/developer-docs/responses#download-a-response-file) exceeds a size limit.

- `Request body too large`: The request body is larger than 4KiB. Shorten `reason` to 500 characters or fewer.
- `File too large`: The file is larger than 500MiB (524,288,000 bytes). This limit applies only when storage reports the file size (`Content-Length`).

---

### 502 Bad Gateway

Returned when [Download a response file](/en/docs/developer-docs/responses#download-a-response-file) cannot fetch the file from storage.

- `Failed to fetch file`: The connection to storage failed or storage responded with an error. This response can also occur when the file is missing from storage.
- `Failed to resolve file`: A download address for protected storage could not be created.
- `Invalid file source`: The stored file address could not be resolved to a storage location. An administrator needs to check the stored address or deployment settings.

**Solution**: If the error is temporary, try again shortly. If it persists, contact an administrator.

### 500 Internal Server Error

Indicates an unexpected error occurred on the server.

**Response:**
```json
{
  "error": "Internal server error"
}
```

**What to Do:**

1. **Retry the Request**: The error may be temporary
2. **Implement Exponential Backoff**: Wait before retrying
3. **Check Status**: Verify if this is a widespread issue
4. **Contact Support**: If the error persists, contact Walla support

**Retry Strategy Example:**

```javascript
async function makeRequestWithRetry(url, options, maxRetries = 3) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      const response = await fetch(url, options);

      if (response.status === 500 && i < maxRetries - 1) {
        // Exponential backoff: 1s, 2s, 4s
        const delay = Math.pow(2, i) * 1000;
        await new Promise(resolve => setTimeout(resolve, delay));
        continue;
      }

      if (!response.ok) {
        throw new Error(`HTTP ${response.status}`);
      }

      return await response.json();
    } catch (error) {
      if (i === maxRetries - 1) throw error;
    }
  }
}
```

```python
import time
import requests

def make_request_with_retry(url, headers, max_retries=3):
    for i in range(max_retries):
        try:
            response = requests.get(url, headers=headers)

            if response.status_code == 500 and i < max_retries - 1:
                # Exponential backoff
                delay = 2 ** i
                time.sleep(delay)
                continue

            response.raise_for_status()
            return response.json()

        except requests.RequestException as e:
            if i == max_retries - 1:
                raise
```

## Error Handling Best Practices

### 1. Always Check Response Status

```javascript
const response = await fetch(url, options);

if (!response.ok) {
  const error = await response.json();
  console.error(`Error ${response.status}:`, error.error);
  throw new Error(error.error);
}

const data = await response.json();
```

### 2. Implement Proper Error Handling

```typescript
try {
  const result = await sendForm(formId, recipients);
  console.log('Success:', result);
} catch (error) {
  if (error.status === 400) {
    console.error('Invalid request:', error.message);
    // Handle validation errors
  } else if (error.status === 401) {
    console.error('Authentication failed');
    // Check API key
  } else if (error.status === 403) {
    console.error('Permission denied');
    // Check API key
  } else if (error.status === 404) {
    console.error('Resource not found');
    // Verify IDs
  } else if (error.status === 429) {
    console.error('Rate limit exceeded');
    // Wait and retry with exponential backoff
  } else if (error.status === 500) {
    console.error('Server error, retrying...');
    // Implement retry logic
  } else {
    console.error('Unexpected error:', error);
  }
}
```

### 3. Log Errors for Debugging

```javascript
function logError(error, context) {
  console.error({
    timestamp: new Date().toISOString(),
    context,
    status: error.status,
    message: error.message,
    stack: error.stack
  });
}

try {
  await api.getResponses(formId);
} catch (error) {
  logError(error, { operation: 'getResponses', formId });
  throw error;
}
```

### 4. Provide User-Friendly Messages

```javascript
function getUserFriendlyError(error) {
  const messages = {
    400: 'Please check your input and try again.',
    401: 'Authentication failed. Please check your API key.',
    403: 'You do not have permission to perform this action.',

    429: 'Too many requests. Please wait a moment and try again.',
    500: 'Something went wrong. Please try again later.'
  };

  return messages[error.status] || 'An unexpected error occurred.';
}
```

## Common Error Scenarios and Solutions

### Scenario 1: "Authentication failed"

**Problem**: Getting 401 errors despite having an API key

**Checklist:**
- [ ] API key is included in the `X-WALLA-API-KEY` header
- [ ] Header name is spelled correctly (case-sensitive)
- [ ] API key is valid and not expired
- [ ] You have access to the requested workspace
- [ ] Using the correct environment's API key

### Scenario 2: "Form not found or not published"

**Problem**: Cannot send form delivery

**Checklist:**
- [ ] Form ID is correct
- [ ] Form exists in your workspace
- [ ] Form is published (not in draft mode)
- [ ] You have permission to access the form

### Scenario 3: "Invalid page number"

**Problem**: Pagination errors when fetching responses

**Checklist:**
- [ ] Page number starts from 1 (not 0)
- [ ] Page number is a positive integer
- [ ] Not exceeding total number of pages

### Scenario 4: Empty response arrays

**Problem**: Getting empty arrays but expecting data

**Possible Reasons:**
- No data exists yet (not an error)
- Incorrect filters or parameters
- Accessing wrong workspace/form
- Data was deleted

**Solution**: Verify the resource has data and you're querying correctly

## Getting Help

If you encounter errors not covered in this documentation:

1. **Check API Response**: The error message often contains helpful details
2. **Review Request**: Verify all required parameters are included
3. **Test with cURL**: Isolate the issue by testing with cURL
4. **Check Permissions**: Ensure you have necessary access rights
5. **Contact Support**: Reach out to Walla support with:
   - Request details (endpoint, method, parameters)
   - Complete error response
   - Timestamp of the error
   - Your workspace/form IDs (if applicable)

# Custom Field SDK

The Custom Field SDK lets you build your own form field types and embed them in Walla forms. Custom fields run inside sandboxed iframes and communicate with the host form through a type-safe, bidirectional RPC channel.

## How It Works

Custom fields are standard HTML pages loaded inside an iframe within a Walla form. The SDK handles all communication between your field and the host form automatically:

```
Host (Walla Form)                      Custom Field (iframe)
       |                                        |
       |-- transfers MessagePort --------------►|  One-time postMessage
       |                                        |
       |         Cap'n Web RPC channel          |
       |◄══════════════════════════════════════►|  Bidirectional RPC
       |                                        |
       |-- init(payload) ---------------------►|
       |◄-- setValue(value) -------------------|
       |-- validate('submit') ----------------►|  Returns Promise
       |◄-- { valid: true } -------------------|
```

1. The host form creates a `MessagePort` and transfers it to your iframe via `postMessage`
2. The SDK establishes a [Cap'n Web RPC](https://github.com/nicolo-ribaudo/capnweb) session over the port
3. All subsequent communication uses type-safe RPC calls — no manual message parsing

You never interact with `MessagePort` or RPC sessions directly. The SDK handles connection setup, protocol negotiation, and message routing for you.

## What You Can Build

Custom fields support a wide range of use cases:

- **Specialized inputs** — color pickers, date range selectors, rich text editors
- **Media capture** — signature pads, audio recorders, camera inputs
- **Data-driven fields** — address autocomplete, product selectors, API-powered lookups
- **Calculated fields** — fields that derive their value from other form fields
- **Embedded experiences** — maps, charts, interactive widgets

## Key Capabilities

- **Theming** — Receive the host form's theme (colors, fonts, border radius) and match your UI to the form design
- **Validation** — Return synchronous or asynchronous validation results during form submission
- **File uploads** — Upload binary data (signatures, recordings) through the host and receive a URL
- **Form context** — Observe other fields' values to build calculated or dependent fields
- **Auto-save** — Every `setValue()` call is automatically persisted by the host

## Security Model

Custom fields run in a sandboxed iframe with `sandbox="allow-scripts"` (no `allow-same-origin`). This means your field:

- **Can** run JavaScript and make network requests
- **Cannot** access the host page's DOM, cookies, or localStorage
- **Cannot** use `localStorage`, `sessionStorage`, or `IndexedDB` within the iframe

All persistent state must go through `setValue()` — the host saves and restores it automatically.

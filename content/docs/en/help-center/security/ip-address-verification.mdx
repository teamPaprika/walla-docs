## Enabling IP Access Restrictions

<Steps>
  <Step>
    ### Open Security settings
    Go to `Team Management` → `Security`.
  </Step>
  <Step>
    ### Turn on IP Access Restrictions and add allowed IPs
    Turn on `IP Access Restrictions` and add your allowed IP addresses or ranges. When IP access restrictions are enabled, at least one IP address or range must be registered.
  </Step>
  <Step>
    ### Review scopes and save
    Confirm the integration scopes below and click `Save Changes`. This setting restricts access to your team's **web dashboard and related APIs**; it does not restrict survey respondents from opening and submitting surveys.
  </Step>
</Steps>

## Applies to
When IP access restrictions are enabled, you can choose which integrations share the allowed IP list below. Changes apply after clicking `Save Changes`.

- `Apply to MCP integrations`: Enforces the allowed IP list on MCP tool calls.
- `Apply to Open API and response integrations`: Covers every Open API call (both API keys and OAuth tokens), response reads through integrations, and attachment downloads.

When you enable IP Access Restrictions for the first time, both scopes are selected by default.

<Callout type="warning" title="Integration Notice">
Cloud integrations use the calling server's public IP address. Applying this restriction may interrupt existing integrations unless those server IPs are added to the allowed list.
</Callout>

## Managing the Allowed IP List
You can register IP addresses or ranges in any of the following formats:

- Individual IP: `192.168.1.1`
- CIDR range: `192.168.1.0/24` (192.168.1.0 to 192.168.1.255)
- Wildcard: `192.168.*.*` (192.168.0.0 to 192.168.255.255)

<Callout type="warning" title="Warning">
Before saving, make sure the allowed list includes your current IP address. Otherwise, you will lose access to the team, even as an administrator.
</Callout>

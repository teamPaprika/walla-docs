---

import { Step, Steps } from 'fumadocs-ui/components/steps';

<Steps>
  <Step>
    ### Register a new store on Toss Payments
    Register a new store on Toss Payments.

    - For details, see the links below.
      - [Toss Payments store registration guide](https://tosspublic.notion.site/b99d2cb71d29401c82eecb64ae6f712c)
      - [Toss Payments fee information](https://www.tosspayments.com/about/fee)
    - If you're already signed up, skip to the next step.
  </Step>
  <Step>
    ### Add a payment field
    Add a payment field in the project editor.
  </Step>
  <Step>
    ### Enter payment details
    Enter the information required for the payment.

    #### Variant key
    - A unique value that identifies a payment UI. You can find it in the payment field under `Check Payment UI variant key`.
    - Be careful to distinguish between live and test UIs — live UIs process real payments, while test UIs do not.
    - If you're new, click `Add UI` to configure a payment UI.
    - After clicking `Add UI`, select `Domestic general payment`.

    <Callout type="warning" title="Virtual accounts are not supported">
    Virtual accounts cannot be used. In the payment UI editor, go to [Features] → [Payment Method List] and make sure to **uncheck** virtual account. Walla records a payment as complete once a response is submitted, but virtual accounts don't settle immediately — which can lead to responses marked as paid even though no deposit has actually been made.
    </Callout>

    #### Client key / secret key
    - You can find these under 'My Developer Info' in the [Toss Payments Developer Center](https://developers.tosspayments.com/). Select your store on the left, then copy the client key and secret key.

    #### Order ID
    - A unique identifier for each order, formatted as 'orderID\_randomKey\_time'. e.g., red bean bungeoppang → `redbean`, custard bungeoppang → `chouxcream`

    #### Product name / price
    - Enter the name and price of the item the respondent is ordering.
  </Step>
  <Step>
    ### Order form complete
    You can now use the payment field to build your order form.

    - When you duplicate a payment field, the secret key is not copied. Enter it again in the duplicated field.
    - Test UIs do not process real payments, so be careful to distinguish them from live UIs.
    - You can use logic to show different payment fields based on the respondent's selections.
  </Step>
</Steps>

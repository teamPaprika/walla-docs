# Error Codes

This guide provides detailed information about error responses you may encounter when using the Walla Open API.

## HTTP Status Codes

The Walla API uses standard HTTP status codes to indicate the success or failure of requests.

### Success Codes

| Code | Status | Description |
|------|--------|-------------|
| 200 | OK | Request succeeded |

### Error Codes

| Code | Status | Description |
|------|--------|-------------|
| 400 | Bad Request | Invalid request parameters or malformed request |
| 403 | Forbidden | Authentication failed or insufficient permissions |
| 404 | Not Found | Resource not found |
| 500 | Internal Server Error | Server error occurred |

## Error Response Format

All error responses follow a consistent JSON format:

```json
{
  "error": "Error message describing what went wrong"
}
```

## Detailed Error Codes

### 400 Bad Request

Indicates that the request was malformed or contains invalid parameters.

**Common Causes:**

1. **Missing Required Fields**
   ```json
   {
     "error": "Invalid request: recipients array is required"
   }
   ```
   **Solution**: Include all required fields in your request body.

2. **Invalid Data Format**
   ```json
   {
     "error": "Invalid email format"
   }
   ```
   **Solution**: Ensure email addresses follow the format `user@domain.com`.

3. **Empty Arrays**
   ```json
   {
     "error": "Recipients array must contain at least one recipient"
   }
   ```
   **Solution**: Provide at least one item in required arrays.

4. **Invalid Pagination Parameters**
   ```json
   {
     "error": "Invalid page number. Page must be >= 1"
   }
   ```
   **Solution**: Use page numbers starting from 1, not 0.

5. **Limit Exceeded**
   ```json
   {
     "error": "Limit cannot exceed 100"
   }
   ```
   **Solution**: Keep the `limit` parameter at or below 100.

**Example Scenarios:**

```javascript
// ❌ Bad - Missing required field
await fetch(`${API_BASE}/forms/form_abc/delivery`, {
  method: 'POST',
  headers: headers,
  body: JSON.stringify({
    // Missing 'recipients' field
    subject: 'Survey'
  })
});
// Returns 400: recipients array is required

// ✅ Good
await fetch(`${API_BASE}/forms/form_abc/delivery`, {
  method: 'POST',
  headers: headers,
  body: JSON.stringify({
    recipients: [
      { customerKey: 'customer_001', email: 'user@example.com' }
    ],
    subject: 'Survey'
  })
});
```

### 403 Forbidden

Indicates authentication failure or insufficient permissions to access the requested resource.

**Common Causes:**

1. **Missing API Key**
   ```json
   {
     "error": "Authentication failed or insufficient permissions"
   }
   ```
   **Solution**: Include the `X-WALLA-API-KEY` header in your request.

2. **Invalid API Key**
   ```json
   {
     "error": "Authentication failed or insufficient permissions"
   }
   ```
   **Solution**: Verify your API key is correct and hasn't expired.

3. **Insufficient Permissions**
   ```json
   {
     "error": "Authentication failed or insufficient permissions"
   }
   ```
   **Solution**: Ensure you have access to the requested workspace or form.

4. **Workspace Access Denied**
   - You're trying to access a workspace you don't have permissions for
   - **Solution**: Contact your workspace administrator to grant access.

**Example Scenarios:**

```javascript
// ❌ Bad - Missing API key
await fetch(`${API_BASE}/workspaces`, {
  method: 'GET',
  headers: {
    'Content-Type': 'application/json'
    // Missing X-WALLA-API-KEY
  }
});
// Returns 403

// ✅ Good
await fetch(`${API_BASE}/workspaces`, {
  method: 'GET',
  headers: {
    'X-WALLA-API-KEY': process.env.WALLA_API_KEY,
    'Content-Type': 'application/json'
  }
});
```

**Troubleshooting Steps:**

1. Verify the API key is correctly set in your environment
2. Check the header name is exactly `X-WALLA-API-KEY` (case-sensitive)
3. Ensure the API key hasn't been revoked or expired
4. Confirm you have access to the requested workspace
5. Verify you're using the correct API key for your environment (dev/staging/production)

### 404 Not Found

Indicates that the requested resource doesn't exist or cannot be accessed.

**Common Causes:**

1. **Form Not Found**
   ```json
   {
     "error": "Form not found"
   }
   ```
   **Solution**: Verify the form ID exists and you have access to it.

2. **Unpublished Form**
   ```json
   {
     "error": "Form not found or not published"
   }
   ```
   **Solution**: Ensure the form is published before attempting to send deliveries.

3. **Response Not Found**
   ```json
   {
     "error": "Form or response not found"
   }
   ```
   **Solution**: Verify both the form ID and response ID are correct.

4. **Workspace Not Found**
   ```json
   {
     "error": "Workspace not found"
   }
   ```
   **Solution**: Check the workspace ID and ensure you have access.

**Example Scenarios:**

```javascript
// ❌ Bad - Trying to send unpublished form
await sendForm('unpublished_form_id', recipients);
// Returns 404: Form not found or not published

// ✅ Good - Form is published
await sendForm('published_form_id', recipients);
```

**Troubleshooting Steps:**

1. Verify the resource ID (form, response, workspace) is correct
2. Check if the form is published (for delivery operations)
3. Ensure the resource hasn't been deleted
4. Confirm you're using the correct environment (dev/production)

### 500 Internal Server Error

Indicates an unexpected error occurred on the server.

**Response:**
```json
{
  "error": "Internal server error"
}
```

**What to Do:**

1. **Retry the Request**: The error may be temporary
2. **Implement Exponential Backoff**: Wait before retrying
3. **Check Status**: Verify if this is a widespread issue
4. **Contact Support**: If the error persists, contact Walla support

**Retry Strategy Example:**

```javascript
async function makeRequestWithRetry(url, options, maxRetries = 3) {
  for (let i = 0; i < maxRetries; i++) {
    try {
      const response = await fetch(url, options);

      if (response.status === 500 && i < maxRetries - 1) {
        // Exponential backoff: 1s, 2s, 4s
        const delay = Math.pow(2, i) * 1000;
        await new Promise(resolve => setTimeout(resolve, delay));
        continue;
      }

      if (!response.ok) {
        throw new Error(`HTTP ${response.status}`);
      }

      return await response.json();
    } catch (error) {
      if (i === maxRetries - 1) throw error;
    }
  }
}
```

```python
import time
import requests

def make_request_with_retry(url, headers, max_retries=3):
    for i in range(max_retries):
        try:
            response = requests.get(url, headers=headers)

            if response.status_code == 500 and i < max_retries - 1:
                # Exponential backoff
                delay = 2 ** i
                time.sleep(delay)
                continue

            response.raise_for_status()
            return response.json()

        except requests.RequestException as e:
            if i == max_retries - 1:
                raise
```

## Error Handling Best Practices

### 1. Always Check Response Status

```javascript
const response = await fetch(url, options);

if (!response.ok) {
  const error = await response.json();
  console.error(`Error ${response.status}:`, error.error);
  throw new Error(error.error);
}

const data = await response.json();
```

### 2. Implement Proper Error Handling

```typescript
try {
  const result = await sendForm(formId, recipients);
  console.log('Success:', result);
} catch (error) {
  if (error.status === 400) {
    console.error('Invalid request:', error.message);
    // Handle validation errors
  } else if (error.status === 403) {
    console.error('Authentication failed');
    // Check API key
  } else if (error.status === 404) {
    console.error('Resource not found');
    // Verify IDs
  } else if (error.status === 500) {
    console.error('Server error, retrying...');
    // Implement retry logic
  } else {
    console.error('Unexpected error:', error);
  }
}
```

### 3. Log Errors for Debugging

```javascript
function logError(error, context) {
  console.error({
    timestamp: new Date().toISOString(),
    context,
    status: error.status,
    message: error.message,
    stack: error.stack
  });
}

try {
  await api.getResponses(formId);
} catch (error) {
  logError(error, { operation: 'getResponses', formId });
  throw error;
}
```

### 4. Provide User-Friendly Messages

```javascript
function getUserFriendlyError(error) {
  const messages = {
    400: 'Please check your input and try again.',
    403: 'You do not have permission to perform this action.',
    404: 'The requested resource was not found.',
    500: 'Something went wrong. Please try again later.'
  };

  return messages[error.status] || 'An unexpected error occurred.';
}
```

### 5. Handle Partial Failures

```javascript
// When sending to multiple recipients
const result = await sendForm(formId, recipients);

  console.warn('Some deliveries failed:');
  result.data.failedDeliveries.forEach(failure => {
    console.error(`${failure.customerKey}: ${failure.error}`);
  });

  // Retry failed deliveries
  const failedRecipients = result.data.failedDeliveries.map(f => ({
    customerKey: f.customerKey,
    email: f.email,
    phoneNumber: f.phoneNumber
  }));

}
```

## Common Error Scenarios and Solutions

### Scenario 1: "Authentication failed"

**Problem**: Getting 403 errors despite having an API key

**Checklist:**
- [ ] API key is included in the `X-WALLA-API-KEY` header
- [ ] Header name is spelled correctly (case-sensitive)
- [ ] API key is valid and not expired
- [ ] You have access to the requested workspace
- [ ] Using the correct environment's API key

### Scenario 2: "Form not found or not published"

**Problem**: Cannot send form delivery

**Checklist:**
- [ ] Form ID is correct
- [ ] Form exists in your workspace
- [ ] Form is published (not in draft mode)
- [ ] You have permission to access the form

### Scenario 3: "Invalid page number"

**Problem**: Pagination errors when fetching responses

**Checklist:**
- [ ] Page number starts from 1 (not 0)
- [ ] Page number is a positive integer
- [ ] Not exceeding total number of pages

### Scenario 4: Empty response arrays

**Problem**: Getting empty arrays but expecting data

**Possible Reasons:**
- No data exists yet (not an error)
- Incorrect filters or parameters
- Accessing wrong workspace/form
- Data was deleted

**Solution**: Verify the resource has data and you're querying correctly

## Getting Help

If you encounter errors not covered in this documentation:

1. **Check API Response**: The error message often contains helpful details
2. **Review Request**: Verify all required parameters are included
3. **Test with cURL**: Isolate the issue by testing with cURL
4. **Check Permissions**: Ensure you have necessary access rights
5. **Contact Support**: Reach out to Walla support with:
   - Request details (endpoint, method, parameters)
   - Complete error response
   - Timestamp of the error
   - Your workspace/form IDs (if applicable)

# Autenticação

A Walla Open API autentica com uma chave de API ou um token de acesso OAuth. Todas as solicitações devem incluir uma dessas credenciais no cabeçalho. Tokens OAuth só podem ser usados em algumas operações de leitura e no download de arquivos de respostas.

## Escolher o método de autenticação

| Item | Chave de API | Token de acesso OAuth |
|------|--------|-------------------|
| Cabeçalho | `X-WALLA-API-KEY: <chave de API>` | `Authorization: Bearer <token de acesso>` |
| Escopo de equipe | A equipe para a qual a chave foi gerada (não é preciso indicar a equipe) | As equipes das quais o usuário do token faz parte. `GET /workspaces` e `GET /forms` exigem `teamId` ([Indicar a equipe](#indicar-a-equipe)) |
| Operações disponíveis | Todas as operações da Open API | Apenas operações de leitura e download de arquivos de respostas ([Escopos e operações permitidas](#escopos-e-operações-permitidas)) |
| Permissões | As permissões vinculadas à chave de API | A participação na equipe, o acesso a espaços de trabalho e as permissões de visualização de respostas e download de arquivos do usuário do token |
| Limite de requisições | 6.000 solicitações por hora por chave de API | Cota por hora por equipe, conforme o plano ([Cota de chamadas com token OAuth](#cota-de-chamadas-com-token-oauth)) |
| Quando usar | Integrações de servidor no nível da equipe e operações de busca, exportação, envio e escrita de respostas | Aplicativos que leem dados dentro das permissões do usuário |

Se os dois cabeçalhos forem enviados, a chave de API prevalece. As integrações existentes com chave de API continuam funcionando da mesma forma.

## Autenticação por chave de API

Inclua a chave no cabeçalho `X-WALLA-API-KEY` de todas as solicitações.

### Formato do cabeçalho

```
X-WALLA-API-KEY: your_api_key_here
```

### Chaves de API por equipe

As chaves de API da Walla são geradas **por equipe**.

- Cada chave está vinculada a uma equipe específica.
- As informações da equipe são incluídas automaticamente nas solicitações.
- Não é necessário informar a equipe separadamente nas chamadas.
- Espaços de trabalho, formulários e respostas são filtrados automaticamente por essa equipe.

## Gerar uma chave de API

1. Entre em [app.walla.my](https://app.walla.my).
2. Acesse [app.walla.my/open-api/doc](https://app.walla.my/open-api/doc).
3. Gere ou copie a chave na seção de chaves de API no topo da página.

> **Importante**: proteja sua chave como uma senha e não a compartilhe publicamente.

## Enviar solicitações autenticadas

Veja como incluir a chave de API em cada linguagem.

### cURL

```bash
curl -X GET "https://api.walla.my/open-api/v1/workspaces" \
  -H "X-WALLA-API-KEY: your_api_key_here" \
  -H "Content-Type: application/json"
```

### JavaScript (Fetch)

```javascript
fetch('https://api.walla.my/open-api/v1/workspaces', {
  method: 'GET',
  headers: {
    'X-WALLA-API-KEY': 'your_api_key_here',
    'Content-Type': 'application/json'
  }
})
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('오류:', error));
```

### Python (requests)

```python
import requests

url = "https://api.walla.my/open-api/v1/workspaces"
headers = {
    "X-WALLA-API-KEY": "your_api_key_here",
    "Content-Type": "application/json"
}

response = requests.get(url, headers=headers)
data = response.json()
print(data)
```

### Node.js (axios)

```javascript
const axios = require('axios');

const config = {
  headers: {
    'X-WALLA-API-KEY': 'your_api_key_here',
    'Content-Type': 'application/json'
  }
};

axios.get('https://api.walla.my/open-api/v1/workspaces', config)
  .then(response => console.log(response.data))
  .catch(error => console.error('오류:', error));
```

## Tokens de acesso OAuth

O token de acesso OAuth é enviado no cabeçalho `Authorization: Bearer <token de acesso>`. As rotas e o formato das respostas são os mesmos das chamadas com chave de API, mas apenas as operações da tabela abaixo podem ser chamadas.

### Obter um token

Os tokens são obtidos pelo fluxo OAuth authorization code. Ao solicitar, observe o seguinte.

- Sempre solicite o escopo `openid`. Sem ele, todas as chamadas retornam `401`, e renovar o token não resolve.
- Solicite os escopos correspondentes às operações que você vai usar (`project:read`, `project:response.read`, `project:response.download`).
- Para poder renovar o token, solicite também `offline_access`. Sem ele, nenhum refresh token é emitido.
- Não envie o parâmetro `resource` (RFC 8707). Se ele for enviado, todas as chamadas com esse token retornam `403 insufficient_scope`.

Em alguns ambientes de implantação (por exemplo, on-premises), a emissão e a renovação de novos tokens podem estar desativadas. Mesmo assim, os tokens já emitidos continuam válidos até expirarem ou serem revogados.

### Escopos e operações permitidas

As rotas são relativas a `/open-api/v1`.

| Escopo | Operações permitidas |
|--------|------------------|
| `project:read` | `GET /teams`<br />`GET /workspaces`, `GET /workspaces/{workspaceId}`, `GET /workspaces/{workspaceId}/forms`<br />`GET /forms`, `GET /forms/{formId}`<br />`GET /forms/{formId}/fields`, `GET /forms/{formId}/fields/{fieldId}`, `GET /forms/{formId}/fields/{fieldId}/description`<br />`GET /forms/{formId}/hidden-fields`<br />`POST /forms/{formId}/exports/field-definitions`<br />`GET /field-output-schemas` |
| `project:response.read` | `GET /forms/{formId}/responses` |
| `project:response.download` | `POST /forms/{formId}/responses/{responseId}/fields/{fieldId}/file` ([Baixar um arquivo de resposta, em inglês](/en/docs/developer-docs/responses#download-a-response-file)) |

**Operações exclusivas da chave de API**: ao chamar as operações abaixo com um token OAuth, a API retorna `403 This endpoint does not accept OAuth tokens`.

- Consultar uma resposta `GET /forms/{formId}/responses/{responseId}`
- Buscar respostas `POST /forms/{formId}/responses/search`
- Exportar respostas `POST /forms/{formId}/exports/responses`
- Envio de formulários (todas as operações em `/forms/{formId}/delivery`)
- Adicionar `POST` e excluir `DELETE` campos ocultos

### Indicar a equipe

Ao chamar `GET /workspaces` ou `GET /forms` com um token OAuth, o parâmetro de consulta `teamId` é obrigatório. Sem ele, a API retorna `400`. Nas chamadas com chave de API, `teamId` é ignorado.

Consulte os IDs de equipe com [`GET /teams` (em inglês)](/en/docs/developer-docs/workspaces#list-teams). Com um token, são retornadas apenas as equipes do usuário do token que passam pela configuração de uso da Open API e pela restrição de acesso por IP.

```json
{
  "success": true,
  "data": [
    { "id": "team_456", "name": "Equipe de marketing", "profileUrl": null }
  ]
}
```

- Convidados sem verificação em duas etapas também veem a equipe na lista, mas as operações dessa equipe retornam `403`.
- Ao chamar `GET /workspaces/{workspaceId}` com um token, se o usuário do token não tiver acesso a esse espaço de trabalho, a API retorna `403 {"error":"Access denied"}`.

### Exemplos de cURL

Os exemplos abaixo pressupõem que um token de acesso já emitido foi salvo na variável de ambiente `WALLA_OAUTH_TOKEN`.

```bash
# 1. Consultar as equipes disponíveis (project:read)
curl -X GET "https://api.walla.my/open-api/v1/teams" \
  -H "Authorization: Bearer $WALLA_OAUTH_TOKEN"

# 2. Consultar os espaços de trabalho da equipe (project:read, teamId obrigatório)
curl -X GET "https://api.walla.my/open-api/v1/workspaces?teamId=team_456" \
  -H "Authorization: Bearer $WALLA_OAUTH_TOKEN"

# 3. Listar as respostas de um formulário (project:response.read)
curl -X GET "https://api.walla.my/open-api/v1/forms/form_abc/responses" \
  -H "Authorization: Bearer $WALLA_OAUTH_TOKEN"
```

Para ver um exemplo de download de arquivos de respostas, consulte [Baixar um arquivo de resposta (em inglês)](/en/docs/developer-docs/responses#download-a-response-file).

## Erros de autenticação

Se a autenticação falhar, serão retornados erros como os seguintes.

### 401 Unauthorized

Ocorre nas seguintes situações.
- A solicitação não contém uma chave de API.
- A chave de API é inválida, expirou ou foi revogada.

**Exemplo de resposta:**

```json
{
  "error": "Unauthorized"
}
```

### 403 Forbidden

Ocorre quando a autenticação é válida, mas você não tem permissão para acessar o recurso.

**Exemplo de resposta:**

```json
{
  "error": "Forbidden"
}
```

### Erros de token OAuth

- **401**: o token é inválido ou expirou. A resposta inclui o cabeçalho `WWW-Authenticate: Bearer error="invalid_token"`. Este é o único caso em que o token deve ser renovado.
- **403 `insufficient_scope`**: falta ao token o escopo necessário. O corpo é `{"error":"insufficient_scope","scope":"<escopo necessário>"}`.
- **403 `This endpoint does not accept OAuth tokens`**: é uma [operação exclusiva da chave de API](#escopos-e-operações-permitidas). Chame-a com uma chave de API.
- **403 `Forbidden`**: você não é membro da equipe, é um convidado sem verificação em duas etapas ou o ID é de um espaço de trabalho ao qual você não tem acesso.
- **403 `Unauthorized`**: o servidor não conseguiu verificar o token. Isso não significa que o token seja inválido; não o renove e tente novamente mais tarde.

Consulte a lista completa de erros em [Códigos de erro](/pt-BR/docs/developer-docs/error-codes).

## Boas práticas

### Segurança

- **Não inclua chaves em commits** — mantenha chaves fora de sistemas de controle de versão, como Git.
- **Use variáveis de ambiente** — gerencie as chaves com variáveis de ambiente.
- **Faça a rotação das chaves** — renove-as periodicamente por segurança.
- **Separe as chaves por ambiente** — use chaves diferentes para desenvolvimento, homologação e produção.

### Variáveis de ambiente

Armazene a chave de API em uma variável de ambiente.

```bash
# Arquivo .env
WALLA_API_KEY=your_api_key_here
```

No código, carregue-a da seguinte forma.

```javascript
// JavaScript
const apiKey = process.env.WALLA_API_KEY;
```

```python
# Python
import os
api_key = os.getenv('WALLA_API_KEY')
```

### Limites de requisições

A Walla Open API aplica limites de requisições para manter a estabilidade do sistema.

- **Limite**: 6.000 solicitações por hora por chave de API
- **Janela de tempo**: 1 hora (janela móvel)

Ao exceder o limite, a API retorna `429 Too Many Requests`. Nesse caso:

- Tente novamente com espera exponencial.
- Armazene as respostas em cache quando possível.
- Reduza solicitações duplicadas desnecessárias.
- Monitore o uso da API.
- Processe solicitações em lote quando possível.

Esses limites se aplicam às chamadas com chave de API.

#### Cota de chamadas com token OAuth

As chamadas com token OAuth são contabilizadas separadamente do limite de 6.000 solicitações por hora da chave de API e estão disponíveis em todos os planos. O plano define apenas a cota. Todos os usuários e aplicativos de uma equipe compartilham a cota dessa equipe.

| Aplica-se a | Cota por hora |
|------|---------------|
| Equipes do plano Free | 600 chamadas |
| Equipes do plano Pro | 3.000 chamadas |
| Equipes dos planos Enterprise e personalizados | 6.000 chamadas |
| `GET /teams`, `GET /field-output-schemas` | 600 chamadas por usuário |

- A janela de 1 hora começa na primeira chamada da equipe (ou do usuário).
- Ao exceder a cota, a API retorna `429 {"error":"rate_limit_exceeded"}` com os cabeçalhos `Retry-After` (em segundos), `RateLimit-Limit`, `RateLimit-Remaining` e `RateLimit-Reset`. Aguarde o tempo indicado em `Retry-After` antes de tentar novamente.
- Chamadas enviadas depois de exceder a cota também são contabilizadas.
- A configuração de uso da Open API da equipe e a restrição de acesso por IP se aplicam independentemente do plano.

## Solução de problemas

### Problemas frequentes

**Problema**: erro 401 mesmo após informar a chave de API

**Solução**:
- Verifique se a chave está correta e não expirou.
- Verifique suas permissões para o espaço de trabalho.
- Verifique se o cabeçalho está escrito exatamente como `X-WALLA-API-KEY`.
- Verifique se o recurso pertence a um espaço de trabalho ao qual você tem acesso.

**Problema**: a chave de API não está sendo enviada

**Solução**:
- Verifique o formato do cabeçalho.
- Verifique se o cliente HTTP inclui os cabeçalhos personalizados.
- Verifique se há erros de digitação no nome do cabeçalho.

**Problema**: erro 400 ao chamar `GET /workspaces` ou `GET /forms` com um token OAuth

**Solução**:
- Inclua o parâmetro de consulta `teamId`. Os IDs de equipe podem ser consultados com `GET /teams`.

**Problema**: chamadas com token OAuth retornam erro 403

**Solução**:
- Se for `insufficient_scope`, verifique se você solicitou o escopo necessário e se não enviou o parâmetro `resource` ao solicitar o token.
- Se for `This endpoint does not accept OAuth tokens`, chame com uma chave de API.
- Se for `Unauthorized`, não renove o token e tente novamente mais tarde.

## Considerações adicionais de segurança

### Proteção das chaves de API

1. **Não grave chaves diretamente no código**
   - Não coloque chaves de API no código-fonte.
   - Use variáveis de ambiente ou um serviço de gerenciamento de segredos.

2. **Use apenas HTTPS**
   - A API só pode ser acessada por HTTPS.
   - Solicitações HTTP são rejeitadas.

3. **Monitore a exposição de chaves**
   - Verifique regularmente se alguma chave foi publicada em um repositório público.
   - Se uma chave for exposta, revogue-a imediatamente e gere outra.

### Gerenciamento de permissões

- As chaves de API estão vinculadas às permissões do espaço de trabalho.
- Gere chaves separadas para cada membro da equipe.
- Revogue imediatamente as chaves que não são mais usadas.
- Revise periodicamente o uso das chaves de API.
- Chamadas com token OAuth seguem a participação na equipe, o acesso a espaços de trabalho e as permissões de visualização de respostas e download de arquivos do usuário do token.

### Boas práticas de tratamento de erros

```javascript
async function makeAuthenticatedRequest(url) {
  try {
    const response = await fetch(url, {
      headers: {
        'X-WALLA-API-KEY': process.env.WALLA_API_KEY,
        'Content-Type': 'application/json'
      }
    });

    if (response.status === 401) {
      console.error('인증 실패: API 키를 확인하세요');
      // Avise o usuário ou inicie um novo processo de autenticação
      return null;
    }

    if (!response.ok) {
      throw new Error(`HTTP 오류! 상태: ${response.status}`);
    }

    return await response.json();
  } catch (error) {
    console.error('요청 실패:', error);
    throw error;
  }
}
```

```python
import requests
import os

def make_authenticated_request(url):
    headers = {
        'X-WALLA-API-KEY': os.getenv('WALLA_API_KEY'),
        'Content-Type': 'application/json'
    }

    try:
        response = requests.get(url, headers=headers)

        if response.status_code == 401:
            print('인증 실패: API 키를 확인하세요')
            return None

        response.raise_for_status()
        return response.json()

    except requests.RequestException as e:
        print(f'요청 실패: {e}')
        raise
```

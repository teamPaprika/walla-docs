# 인증

Walla Open API는 API 키 또는 OAuth 액세스 토큰으로 인증합니다. 모든 API 요청에는 둘 중 하나를 헤더에 포함해야 합니다. OAuth 토큰은 일부 읽기 작업과 응답 파일 다운로드에만 사용할 수 있습니다.

## 인증 방식 선택

| 항목 | API 키 | OAuth 액세스 토큰 |
|------|--------|-------------------|
| 헤더 | `X-WALLA-API-KEY: <API 키>` | `Authorization: Bearer <액세스 토큰>` |
| 팀 범위 | 키가 발급된 팀 (팀 지정 불필요) | 토큰 사용자가 속한 팀. `GET /workspaces`·`GET /forms`에는 `teamId` 필요 ([팀 지정](#팀-지정)) |
| 사용 가능한 작업 | 모든 Open API 작업 | 읽기 작업과 응답 파일 다운로드만 ([스코프와 사용 가능한 작업](#스코프와-사용-가능한-작업)) |
| 권한 | API 키에 연결된 권한 | 토큰 사용자의 팀 멤버십·워크스페이스 접근·응답 조회·파일 다운로드 권한 |
| 속도 제한 | API 키당 시간당 6,000건 | 플랜별 팀 단위 시간당 허용량 ([OAuth 토큰 호출 허용량](#oauth-토큰-호출-허용량)) |
| 적합한 경우 | 팀 단위 서버 연동, 응답 검색·내보내기·발송·쓰기 작업 | 사용자 권한 범위 안에서 데이터를 읽는 앱 |

두 헤더를 함께 보내면 API 키가 우선 적용됩니다. 기존 API 키 연동은 지금과 동일하게 동작합니다.

## API 키 인증

모든 요청의 `X-WALLA-API-KEY` 헤더에 API 키를 포함하세요.

### 헤더 형식

```
X-WALLA-API-KEY: your_api_key_here
```

### 팀 범위 API 키

Walla API 키는 **팀 단위**로 생성됩니다.

- 각 API 키는 특정 팀에 연결됩니다
- 팀 정보는 모든 요청에 자동으로 포함됩니다
- API 호출 시 별도로 팀 정보를 전달하지 않아도 됩니다
- 워크스페이스, 폼, 응답은 자동으로 해당 팀 범위로 필터링됩니다

## API 키 발급받기

1. [app.walla.my](https://app.walla.my)에 로그인합니다
2. [app.walla.my/open-api/doc](https://app.walla.my/open-api/doc)으로 이동합니다
3. 페이지 상단의 API 키 섹션에서 키를 생성하거나 복사합니다

> **중요**: API 키는 비밀번호처럼 안전하게 보관하고, 외부에 공유하지 마세요.

## 인증된 요청 보내기

각 언어별로 API 키를 포함하는 방법은 다음과 같습니다.

### cURL

```bash
curl -X GET "https://api.walla.my/open-api/v1/workspaces" \
  -H "X-WALLA-API-KEY: your_api_key_here" \
  -H "Content-Type: application/json"
```

### JavaScript (Fetch)

```javascript
fetch('https://api.walla.my/open-api/v1/workspaces', {
  method: 'GET',
  headers: {
    'X-WALLA-API-KEY': 'your_api_key_here',
    'Content-Type': 'application/json'
  }
})
  .then(response => response.json())
  .then(data => console.log(data))
  .catch(error => console.error('오류:', error));
```

### Python (requests)

```python
import requests

url = "https://api.walla.my/open-api/v1/workspaces"
headers = {
    "X-WALLA-API-KEY": "your_api_key_here",
    "Content-Type": "application/json"
}

response = requests.get(url, headers=headers)
data = response.json()
print(data)
```

### Node.js (axios)

```javascript
const axios = require('axios');

const config = {
  headers: {
    'X-WALLA-API-KEY': 'your_api_key_here',
    'Content-Type': 'application/json'
  }
};

axios.get('https://api.walla.my/open-api/v1/workspaces', config)
  .then(response => console.log(response.data))
  .catch(error => console.error('오류:', error));
```

## OAuth 액세스 토큰

OAuth 액세스 토큰은 `Authorization: Bearer <액세스 토큰>` 헤더로 보냅니다. 경로와 응답 형식은 API 키 호출과 같습니다. 단, 아래 표의 작업만 호출할 수 있습니다.

### 토큰 받기

토큰은 OAuth authorization code 흐름으로 받습니다. 요청할 때 아래 사항을 지켜주세요.

- `openid` 스코프를 반드시 함께 요청하세요. 빠지면 모든 호출이 `401`이며, 토큰을 갱신해도 해결되지 않습니다.
- 사용할 작업에 맞는 스코프(`project:read`, `project:response.read`, `project:response.download`)를 요청하세요.
- 토큰을 갱신하려면 `offline_access`도 요청하세요. 없으면 refresh 토큰이 발급되지 않습니다.
- `resource` 파라미터(RFC 8707)는 보내지 마세요. 보내면 그 토큰으로 하는 모든 호출이 `403 insufficient_scope`입니다.

일부 배포 환경(예: 온프레미스)에서는 새 토큰 발급·갱신이 중지되어 있을 수 있습니다. 이 경우에도 이미 발급된 토큰은 만료되거나 폐기될 때까지 사용할 수 있습니다.

### 스코프와 사용 가능한 작업

경로는 `/open-api/v1` 기준입니다.

| 스코프 | 사용 가능한 작업 |
|--------|------------------|
| `project:read` | `GET /teams`<br />`GET /workspaces`, `GET /workspaces/{workspaceId}`, `GET /workspaces/{workspaceId}/forms`<br />`GET /forms`, `GET /forms/{formId}`<br />`GET /forms/{formId}/fields`, `GET /forms/{formId}/fields/{fieldId}`, `GET /forms/{formId}/fields/{fieldId}/description`<br />`GET /forms/{formId}/hidden-fields`<br />`POST /forms/{formId}/exports/field-definitions`<br />`GET /field-output-schemas` |
| `project:response.read` | `GET /forms/{formId}/responses` |
| `project:response.download` | `POST /forms/{formId}/responses/{responseId}/fields/{fieldId}/file` ([응답 파일 다운로드](/ko/docs/developer-docs/responses#응답-파일-다운로드)) |

**API 키 전용 작업**: 아래 작업은 OAuth 토큰으로 호출하면 `403 This endpoint does not accept OAuth tokens`를 반환합니다.

- 특정 응답 조회 `GET /forms/{formId}/responses/{responseId}`
- 응답 검색 `POST /forms/{formId}/responses/search`
- 응답 내보내기 `POST /forms/{formId}/exports/responses`
- 폼 발송(`/forms/{formId}/delivery` 아래의 모든 작업)
- 히든 필드 추가 `POST`·삭제 `DELETE`

### 팀 지정

OAuth 토큰으로 `GET /workspaces`나 `GET /forms`를 호출할 때는 `teamId` 쿼리 파라미터가 필요합니다. 빠지면 `400`을 반환합니다. API 키 호출에서는 `teamId`를 무시합니다.

팀 ID는 [`GET /teams`](/ko/docs/developer-docs/workspaces#팀-목록-조회)로 확인하세요. 토큰으로 호출하면 토큰 사용자가 속한 팀 중 Open API 사용 설정과 IP 접근 제한을 통과하는 팀만 반환합니다.

```json
{
  "success": true,
  "data": [
    { "id": "team_456", "name": "마케팅 팀", "profileUrl": null }
  ]
}
```

- 2단계 인증을 켜지 않은 게스트에게도 팀이 목록에 표시되지만, 그 팀의 작업은 `403`을 반환합니다.
- 토큰으로 `GET /workspaces/{workspaceId}`를 호출할 때 토큰 사용자가 그 워크스페이스에 접근할 수 없으면 `403 {"error":"Access denied"}`를 반환합니다.

### cURL 예시

아래 예시는 이미 발급받은 액세스 토큰을 `WALLA_OAUTH_TOKEN` 환경 변수에 저장했다고 가정합니다.

```bash
# 1. 호출 가능한 팀 조회 (project:read)
curl -X GET "https://api.walla.my/open-api/v1/teams" \
  -H "Authorization: Bearer $WALLA_OAUTH_TOKEN"

# 2. 팀의 워크스페이스 조회 (project:read, teamId 필수)
curl -X GET "https://api.walla.my/open-api/v1/workspaces?teamId=team_456" \
  -H "Authorization: Bearer $WALLA_OAUTH_TOKEN"

# 3. 폼 응답 목록 조회 (project:response.read)
curl -X GET "https://api.walla.my/open-api/v1/forms/form_abc/responses" \
  -H "Authorization: Bearer $WALLA_OAUTH_TOKEN"
```

응답 파일 다운로드 예시는 [응답 파일 다운로드](/ko/docs/developer-docs/responses#응답-파일-다운로드)를 참고하세요.

## 인증 오류

인증에 실패하면 아래와 같은 오류가 반환됩니다.

### 401 Unauthorized

다음 경우에 발생합니다.
- 요청에 API 키가 빠져 있는 경우
- API 키가 유효하지 않거나 만료·취소된 경우

**응답 예시:**

```json
{
  "error": "Unauthorized"
}
```

### 403 Forbidden

인증은 통과했지만 해당 리소스에 접근할 권한이 없는 경우 발생합니다.

**응답 예시:**

```json
{
  "error": "Forbidden"
}
```

### OAuth 토큰 오류

- **401**: 토큰이 유효하지 않거나 만료되었습니다. 응답에 `WWW-Authenticate: Bearer error="invalid_token"` 헤더가 포함됩니다. 토큰을 갱신해야 하는 경우는 이것뿐입니다.
- **403 `insufficient_scope`**: 토큰에 필요한 스코프가 없습니다. 본문은 `{"error":"insufficient_scope","scope":"<필요한 스코프>"}`입니다.
- **403 `This endpoint does not accept OAuth tokens`**: [API 키 전용 작업](#스코프와-사용-가능한-작업)입니다. API 키로 호출하세요.
- **403 `Forbidden`**: 팀 멤버가 아니거나, 2단계 인증을 켜지 않은 게스트이거나, 접근할 수 없는 워크스페이스 ID입니다.
- **403 `Unauthorized`**: 서버가 토큰을 확인하지 못했습니다. 토큰이 무효하다는 뜻이 아니므로 갱신하지 말고 잠시 후 다시 시도하세요.

전체 오류 목록은 [오류 코드](/ko/docs/developer-docs/error-codes)를 참고하세요.

## 모범 사례

### 보안

- **API 키를 커밋하지 마세요** - Git 등 버전 관리 시스템에 API 키를 포함하지 마세요
- **환경 변수를 사용하세요** - API 키는 환경 변수로 관리하세요
- **키를 정기적으로 교체하세요** - 보안을 위해 주기적으로 키를 갱신하세요
- **환경별로 키를 분리하세요** - 개발, 스테이징, 프로덕션 환경에 각각 다른 키를 사용하세요

### 환경 변수

API 키를 환경 변수에 저장하세요.

```bash
# .env 파일
WALLA_API_KEY=your_api_key_here
```

코드에서는 아래와 같이 불러올 수 있습니다.

```javascript
// JavaScript
const apiKey = process.env.WALLA_API_KEY;
```

```python
# Python
import os
api_key = os.getenv('WALLA_API_KEY')
```

### 속도 제한

Walla Open API에는 시스템 안정성을 위한 속도 제한이 적용됩니다.

- **제한**: API 키당 시간당 6,000건
- **시간 윈도우**: 1시간 (롤링 윈도우)

속도 제한을 초과하면 `429 Too Many Requests` 응답이 반환됩니다. 이 경우:

- 지수 백오프로 재시도하세요
- 가능하면 응답을 캐시하세요
- 불필요한 중복 요청을 줄이세요
- API 사용량을 모니터링하세요
- 가능하면 요청을 일괄 처리하세요

위 제한은 API 키 호출에 적용됩니다.

#### OAuth 토큰 호출 허용량

OAuth 토큰 호출은 API 키의 시간당 6,000건 제한과 별도로 집계되며, 모든 플랜에서 사용할 수 있습니다. 플랜은 허용량만 정합니다. 팀 하나의 허용량을 그 팀의 모든 사용자와 앱이 함께 사용합니다.

| 대상 | 시간당 허용량 |
|------|---------------|
| Free 플랜 팀 | 600건 |
| Pro 플랜 팀 | 3,000건 |
| Enterprise·커스텀 플랜 팀 | 6,000건 |
| `GET /teams`, `GET /field-output-schemas` | 사용자당 600건 |

- 1시간 윈도우는 해당 팀(또는 사용자)의 첫 호출부터 시작합니다.
- 허용량을 넘으면 `429 {"error":"rate_limit_exceeded"}`를 반환하며, `Retry-After`(초), `RateLimit-Limit`, `RateLimit-Remaining`, `RateLimit-Reset` 헤더가 포함됩니다. `Retry-After`만큼 기다린 뒤 다시 시도하세요.
- 허용량을 넘긴 뒤에 보낸 호출도 횟수에 포함됩니다.
- 팀의 Open API 사용 설정과 IP 접근 제한은 플랜과 관계없이 적용됩니다.

## 문제 해결

### 자주 발생하는 문제

**문제**: API 키를 넣었는데도 401 오류가 발생함

**해결 방법**:
- API 키가 올바르고 만료되지 않았는지 확인하세요
- 해당 워크스페이스에 대한 권한이 있는지 확인하세요
- 헤더 이름이 정확히 `X-WALLA-API-KEY`인지 확인하세요 (대소문자 구분)
- 접근 권한이 있는 워크스페이스의 리소스인지 확인하세요

**문제**: API 키가 전달되지 않음

**해결 방법**:
- 헤더 형식이 올바른지 확인하세요
- HTTP 클라이언트에서 커스텀 헤더가 포함되는지 확인하세요
- 헤더 이름에 오타가 없는지 확인하세요

**문제**: OAuth 토큰으로 `GET /workspaces` 또는 `GET /forms`를 호출하면 400 오류가 발생함

**해결 방법**:
- `teamId` 쿼리 파라미터를 포함하세요. 팀 ID는 `GET /teams`로 확인할 수 있습니다

**문제**: OAuth 토큰 호출이 403 오류를 반환함

**해결 방법**:
- `insufficient_scope`이면 필요한 스코프를 요청했는지, 토큰 요청에 `resource` 파라미터를 보내지 않았는지 확인하세요
- `This endpoint does not accept OAuth tokens`이면 API 키로 호출하세요
- `Unauthorized`이면 토큰을 갱신하지 말고 잠시 후 다시 시도하세요

## 추가 보안 고려사항

### API 키 보호

1. **코드에 하드코딩하지 마세요**
   - 소스 코드에 API 키를 직접 넣지 마세요
   - 환경 변수나 시크릿 관리 서비스를 사용하세요

2. **HTTPS만 사용하세요**
   - API는 HTTPS로만 접근할 수 있습니다
   - HTTP 요청은 거부됩니다

3. **키 노출 모니터링**
   - 공개 저장소에 키가 올라가지 않았는지 정기적으로 확인하세요
   - 키가 노출된 경우 즉시 폐기하고 새로 발급하세요

### 권한 관리

- API 키는 워크스페이스 권한과 연결됩니다
- 팀 멤버별로 별도의 API 키를 발급하세요
- 사용하지 않는 키는 바로 폐기하세요
- API 키 사용 현황을 주기적으로 점검하세요
- OAuth 토큰 호출에는 토큰 사용자의 팀 멤버십, 워크스페이스 접근 권한, 응답 조회·파일 다운로드 권한이 적용됩니다

### 에러 처리 모범 사례

```javascript
async function makeAuthenticatedRequest(url) {
  try {
    const response = await fetch(url, {
      headers: {
        'X-WALLA-API-KEY': process.env.WALLA_API_KEY,
        'Content-Type': 'application/json'
      }
    });

    if (response.status === 401) {
      console.error('인증 실패: API 키를 확인하세요');
      // 사용자에게 알리거나 재인증 프로세스 시작
      return null;
    }

    if (!response.ok) {
      throw new Error(`HTTP 오류! 상태: ${response.status}`);
    }

    return await response.json();
  } catch (error) {
    console.error('요청 실패:', error);
    throw error;
  }
}
```

```python
import requests
import os

def make_authenticated_request(url):
    headers = {
        'X-WALLA-API-KEY': os.getenv('WALLA_API_KEY'),
        'Content-Type': 'application/json'
    }

    try:
        response = requests.get(url, headers=headers)

        if response.status_code == 401:
            print('인증 실패: API 키를 확인하세요')
            return None

        response.raise_for_status()
        return response.json()

    except requests.RequestException as e:
        print(f'요청 실패: {e}')
        raise
```

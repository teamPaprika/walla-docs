# walla-docs:deploy

문서 사이트에 변경 사항을 반영(배포)하는 스킬입니다.
비개발자도 쉽게 사용할 수 있도록, git/PR 같은 기술 용어는 사용하지 않고 안내합니다.

## 워크플로우

### 1단계: 변경 내용 요약

변경된 파일을 확인하고, 사용자에게 **쉬운 말로** 요약합니다:

```
수정된 내용을 정리했어요:

- 새 페이지 추가: "AI로 설문 만들기" (한국어, 영어)
- 수정: 헬프센터 메뉴 순서 변경

이대로 진행할까요?
```

기술적인 내용(파일 경로, git diff 등)은 보여주지 않습니다.

### 2단계: 빌드 검증

```bash
pnpm build
```

- 문제가 없으면 사용자에게 알리지 않고 다음 단계로
- 에러가 있으면 **쉬운 말로 설명**:
  - "'{파일명}' 페이지에 문법 오류가 있어요. 수정할게요!" → 자동 수정 시도
  - 자동 수정이 안 되면 구체적으로 어떤 부분이 문제인지 안내

### 3단계: 브라우저에서 미리보기

개발 서버를 확인하고 미리보기 URL을 안내합니다:

```bash
# 개발 서버가 실행 중인지 확인
lsof -i :3000 -sTCP:LISTEN
```

실행 중이 아니면 시작합니다:
```bash
pnpm dev
```

사용자에게 안내:
```
브라우저에서 수정된 내용을 확인해보세요:

  👉 http://localhost:3000/ko/docs/help-center/create-forms/creating-project-ai

확인하시고 문제없으면 "배포해줘"라고 말씀해주세요!
```

- 변경된 페이지의 URL을 직접 알려줍니다
- 여러 페이지가 변경됐으면 각각의 URL을 나열합니다

### 4단계: 배포 승인 대기

사용자가 "배포해줘", "반영해줘", "올려줘" 등으로 승인할 때까지 **절대 배포하지 않습니다**.

### 5단계: 배포 실행

승인받으면 내부적으로 처리합니다 (사용자에게 기술적 과정은 보여주지 않음):

1. 새 브랜치 생성 & 변경사항 커밋
2. PR 생성
3. PR 머지 (→ main 브랜치에 반영 → GitHub Actions 자동 배포)

```bash
git checkout -b docs/자동생성-브랜치명
git add 변경된파일들
git commit -m "커밋 메시지"
git push -u origin HEAD
gh pr create --title "제목" --body "내용"
gh pr merge --merge
git checkout main
git pull
```

### 6단계: 배포 완료 확인

```bash
gh run list --workflow=deploy.yml --limit=1
```

사용자에게:
```
배포가 진행 중이에요. 보통 1~2분 정도 걸려요.
```

배포 완료 후:
```
배포가 완료됐어요! 실제 사이트에서 확인해보세요:
  👉 https://docs.walla.my (또는 실제 도메인)
```

실패 시:
```
배포 중 문제가 발생했어요. 원인을 확인해볼게요...
```
→ 에러 로그를 확인하고 쉬운 말로 설명

## 사용자 커뮤니케이션 규칙

- git, branch, PR, merge, commit 같은 용어를 사용하지 않음
- "수정 사항", "반영", "배포", "사이트에 올리기" 같은 표현 사용
- 기술적 과정은 내부적으로 처리하고 결과만 알려줌
- 에러 발생 시 기술적 메시지가 아닌 "무엇이 잘못됐고, 어떻게 하면 되는지"를 안내

## 주의사항

- 사용자 승인 없이 절대 배포하지 않음
- 빌드 실패 시 절대 강제 배포하지 않음
- 민감한 정보(.env 등)가 포함되지 않았는지 확인
- 배포 후 반드시 실제 사이트 반영 여부 확인
